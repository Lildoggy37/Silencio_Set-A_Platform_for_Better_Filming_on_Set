# 剧本文件导入与原文核对

DOCX、文字型PDF、UTF-8 TXT导入已接通前后端，迁移头`0019_script_imports`。导入创建待核对版本，保留私有原文件，不自动确认正文或替换工作稿。既有文本录入流程继续使用。

## 使用与接口

先在项目资料中创建／选择剧本，再选择“导入文件新版本”，核对文件并明确提交。成功后查看提取正文、提示及PDF来源页码；可下载原文对照。修正、确认和切换工作版本仍为独立操作。修正导入正文后保留原文件，但清除段落的来源页码，避免将修改后的段落误标到原文。

| 接口 | 契约 |
|---|---|
| POST `/api/v1/crews/{crew}/scripts/{script}/imports` | multipart/form-data：file、expected_lock_version；会话、CSRF与UUID Idempotency-Key；成功201返回ScriptResult |
| GET `/api/v1/crews/{crew}/scripts/{script}/versions/{version}/source-file` | 按当前script.read和同组／同剧本／版本引用鉴权，返回attachment文件流；无原件或无权隐藏404 |

导入要求script.read及script.edit。来源文件格式由实际解析检查，客户端MIME类型不作可信依据；文件名只保存去除路径的显示名称，不参与存储路径生成。版本详情新增source_file，可空；非空时包含id、original_name、file_format、byte_size、page_count、extraction_notes。不返回磁盘路径、存储键或摘要。

## 提取范围与限制

- 单文件最多20×1024×1024字节，正文按非空行编号，连同段落间换行最多100000字符；PDF最多100页。上传端整体请求另允许64KiB表单封装开销。
- DOCX按正文与表格阅读顺序提取，合并单元格去重；不还原排版，不提供可靠页码。图片、文本框、页眉页脚、脚注及修订内容仍须人工核对。压缩包展开声明总量最多64MiB，拒绝宏包及非DOCX内容。
- PDF提取文本层并保留原页码。排版、文字顺序、断行可能变化；部分页面无文字时明确列出页码，全部无文字则拒绝。拒绝加密PDF，不接入OCR，也不推测图片中的正文。
- TXT要求UTF-8，可有BOM；其他编码需转换或改用粘贴正文。
- 解析失败、超限、超时不会创建成功版本。原始文件中的内容仅作数据处理，不执行文档脚本或访问外部链接。

实现基于python-docx 1.2.0、pypdf 6.21.4和python-multipart 0.0.33，运行及开发依赖锁已同步，仅新增这三项及lxml 6.1.3，未升级其他锁定依赖。阅读顺序与提取局限参考[python-docx文档](https://python-docx.readthedocs.io/en/latest/api/document.html#docx.document.Document.iter_inner_content)、[pypdf文本提取说明](https://pypdf.readthedocs.io/en/stable/user/extract-text.html)。

## 事务、幂等与文件存储

导入先短事务验证权限、剧本版本及既有回执，再释放协调锁执行解析；提交时再次在既有剧组协调事务内检查权限、版本及回执。幂等摘要绑定剧本、原文件名称、格式、字节数、SHA-256和预期版本。已成功请求重放原结果，不因剧本版本已变化而重复解析；同键不同文件或入组身份变化拒绝重放。

新增script_source_files，记录原件元数据、私有存储键、提取提示及上传成员；script_versions.source_file_id通过同剧组、同剧本复合外键关联。文件元数据、待核对版本、段落、剧本锁版本、审计及成功回执共同提交。PDF页码存入ScriptParagraph.source_page，原有文字录入仍为空。

原件默认保存在`<仓库>/runtime/private-script-files`，目录已被Git忽略，不挂载为静态资源。可用SCRIPT_STORAGE_ROOT指定私有绝对目录；示例配置仅给出注释，不修改实际.env。API进程需要读写该目录，备份时须同时保存数据库和私有目录。

文件写入先于数据库提交。数据库失败、提交结果未知、并发同键或最终权限变化时，可能留下无数据库引用的私有文件；不会为清理孤立文件冒险删除可能已经提交成功的原件。当前没有自动清理或磁盘总额配额，后续需结合数据库引用核对补充维护工具；不能把文件系统写入称为数据库原子事务。

## 本批设计取舍

原设计描述通用files上传、异步解析及202任务ID。本批采用绑定剧本的导入接口，由受限子进程直接返回提取完成后的201结果；未伪造后台任务、解析中状态或任务进度。现有正文版本状态仍为pending_check／confirmed。此为文件导入实现方式调整，保留原需求的文件类型、人工核对、版本与权限边界。

解析在独立Python进程中运行，每次最多30秒，超时终止；每个API进程同时最多2个解析进程，等待发生在请求内。前端上传请求超时60秒，结果不明时冻结文件、版本前提和幂等键，提供原请求手动重试。解析不持有数据库协调锁，不占用事件循环执行文档解析。

当前没有操作系统级子进程内存硬配额，不能据大小或超时限制声称已防止所有解析资源耗尽；大文件处理、排队容量、进程恢复、真实性能仍待实测。RabbitMQ仍用于已有后台业务，本批未新增文档解析任务；[通告PDF导出](call-sheet-pdf.md)已接入；[勘景照片](location-scouting.md)已接入；通用文件中心仍待接入。
