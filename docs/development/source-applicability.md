# 剧本变更影响与来源适用性复核

本批补齐旧场戏／文字分镜对当前工作稿的适用性记录、历史与排期衔接。迁移头`0023_source_reviews`，仅完成离线SQL验证，未执行真实数据库迁移。

## 业务范围

资料仍绑定创建时的剧本或场戏修订，已确认内容不覆盖。工作稿变化后，剧本资料页可按场戏拆解／文字分镜分页列出固定来源不同于工作稿的资料，包括已复核仍适用项；不把空列表当作筹备全部就绪。

有对应读取权限的成员可查看来源状态、原稿和工作稿文字；只有`script.read + scene.read + scene.review`（场戏）或`script.read + storyboard.read + storyboard.review`（分镜）才能记录复核。管理员身份、制片发布权和编剧编辑权不代替资料审核权。

只对**已确认且固定来源不同于当前工作稿**的资料记录适用性。草稿、待审或退回资料需先完成内容审核；资料内容审核与对新工作稿的适用性是两项不同结论。复核要求1—1000字依据，结论只能为：

- `still_applicable`：核对后该整份拆解／分镜在当前工作稿下仍适用。
- `needs_revision`：需要基于工作稿新建资料，不能沿用为就绪依据。

原稿和工作稿按固定版本分别展开显示，段落编号保留；这不是自动文本差异、别名匹配或艺术质量判断。分镜和场戏分别复核，结论不会互相推断。跨来源自动复制／段落映射尚未实现。

## 来源依据与存储

`scripts.working_revision`初值0；首次设工作稿及每次切换到不同版本加1，迁移将已有工作稿回填为1。重复选择同一工作稿不增加该序号，也不重复触发来源变化；导入新稿、人物绑定等操作仍可增加`Script.lock_version`，但不改变工作稿序号。

新增`source_review_records`，保存同剧组的拆解或分镜目标（二选一）、剧本、固定原稿、当前工作稿、工作稿序号、目标锁版本、实际审核成员及当时入组时间、结论、依据和时间。记录只追加，旧记录不覆盖；原资料、正式排期和通告快照均不改写。

有效结论必须同时匹配目标ID／锁版本、原稿ID、当前工作稿ID和工作稿序号，取该依据下最新记录。例如资料来源A，工作稿B→A→B，第一次B下的结论不能沿用到第二次B。审核人后来离组不删除当时合法作出的记录；再次提交仍需重新检查当前权限。

## 并发与幂等

复核使用既有剧组协调事务。输入同时包含目标锁、预期工作稿ID／序号、上一条有效复核ID（可空），防止换稿或另一位审核人提交后静默覆盖依据。权限、目标、工作稿及上一结论全部匹配才追加记录。

复用`creative_action_receipts`，摘要包含目标类别、目标ID和完整请求。同键重试先检查当前操作者权限／入组身份，再返回原响应；不重复记录、不再次发送影响事件。重放响应仍代表原提交时依据，前端成功后重新GET当前状态，不将旧响应当作新工作稿结论。

资料复核记录、受影响排期／通告标记、审计和幂等回执在同一事务提交。工作稿切换仍在原剧本写事务内标记当前关联排期待复核。

## 排期及通告衔接

排期预检批量读取来源拆解的有效复核。固定来源就是工作稿时直接按正常规则检查；来源不同但有当前有效`still_applicable`记录时，仅解除“来源不同”这一项阻塞。无结论或`needs_revision`继续返回`SOURCE_REVIEW_REQUIRED`。人员、演员、档期、预约及库存等既有检查全部保留。

预检／发布指纹增加来源复核ID、适用布尔值及工作稿序号。复核结论变更、再次换稿或新增记录后，旧预检不能直接发布。分镜未被排期显式引用，因此不声称已校验某个分镜版本对计划的直接影响。

场戏复核结论新增或变更时，只标记引用该拆解且尚未结束的当前正式排期为`source_review_changed`，继而标记相关当前通告待复核。即使结论为仍适用，也不自动清除原排期标记、恢复旧通告或迁移成员知悉。制片仍需复制／创建草稿、检查、重新发布安排和通告。已发布快照和旧回执保留。

## 接口

路径均位于`/api/v1/crews/{crew_id}`，`kind=breakdowns/storyboards`。列表每页20项，沿用创作读取120次／分钟、写入10次／分钟的账号及IP限流。

| 方法与路径 | 说明 |
|---|---|
| GET `/scripts/{id}/source-impacts?kind=...&page=...` | 同剧本、按对应资料读取权过滤，返回来源不同的资料及最新有效结论 |
| GET `/{kind}/{id}/source-assessment` | 固定原稿、当前工作稿、工作稿序号、目标版本及来源状态 |
| GET `/{kind}/{id}/source-reviews?page=...` | 该目标的历史复核分页，不删除过期依据 |
| POST `/{kind}/{id}/source-reviews` | CSRF及UUID幂等键；成功201，返回原操作对应的来源评估 |

POST字段：`expected_lock_version`、`expected_working_version_id`、`expected_working_revision`、`expected_review_id`、`conclusion`、`review_note`。

主要冲突：`SOURCE_TARGET_NOT_CONFIRMED`、`SOURCE_BASIS_CHANGED`、`SOURCE_REVIEW_CHANGED`、`SOURCE_REVIEW_NOT_REQUIRED`、既有版本／幂等／身份冲突，均为409；缺少读取／审核权403，异组或未知对象404，无效输入422，服务故障脱敏503。

## 页面与验证边界

剧本资料增加“查看剧本变更影响”，可进入固定历史资料；场戏／分镜详情增加“检查资料来源”，按需读取来源、两版正文及历史。复核先填写结论和依据，再明确确认。结果未知保留原请求与键手动重试；已知冲突保留说明，刷新依据并重新确认，不自动套用旧结论。读取失败隐藏原缓存资料。

本批采用实时来源评估及追加复核记录，尚未引入完整设计中的通用`impact_issues/impact_check_states`持久问题池、异步检查状态、跨类提醒去重；资源／档期影响继续使用既有排期标记与正式发布实时校验。该实现差异不代表这些设计范围已经取消。

定向测试覆盖工作稿往返、权限、目标及结论竞争、重复请求、事务失败、历史分页、精确排期影响、真实预检组合、输入和HTTP约束、文字对照及前端确认／重试。迁移仅离线校验；真实数据库并发、浏览器视觉和性能验收仍待完成。

后续统一只读变更清单已接入总览，按已有业务事实汇总并定位处理，见[变更工作台说明](change-workbench.md)。通用持久问题池及异步检查状态仍未实现。
