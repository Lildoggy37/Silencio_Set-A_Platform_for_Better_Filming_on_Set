# 剧组基础：创建、选择与在组成员

阶段记录：本页保留剧组基础四个接口及创建/选择、成员目录阶段的32项前端、235项后端测试快照。后续岗位管理与末位管理员保护已实现，最新状态见[岗位管理说明](member-roles.md)。数据库与队列仍用测试替身，真实PostgreSQL迁移、并发和容器联调未完成，浏览器视觉检查也未完成。

## 1. 核心代码及需求对应

对应FR-01、BR-01—03、NFR-03及D03第3/4/27节、D05第6节、D10权限矩阵。没有增加业务需求，本批只实现其基础子集。

## 2. 接口与约束

| 接口 | 当前行为 |
|---|---|
| `POST /api/v1/crews` | `name`1—50、`project_name`1—100、可空`description`最多1000个Unicode码点；去首尾空白，拒绝控制字符，说明允许换行/Tab。额外身份/岗位字段拒绝。成功201 |
| `GET /api/v1/crews` | 只返回本人仍在组、具有`crew.read`的剧组，带本人成员摘要及有效权限 |
| `GET /api/v1/crews/{crew_id}` | 再次按当前成员身份检查；不存在、不在组、已离组或无读取权均返回隐藏404 |
| `GET /api/v1/crews/{crew_id}/members` | 同组且具有`member.read`才能读取；本批仅支持`status=active`，不开放历史目录 |

分页默认`page=1/page_size=20`，每页最多100，页码上限100000，排序具有UUID次级顺序。前端每页20条，不使用无限量列表。目录只返回成员标识、显示名、状态、岗位及版本，不返回邮箱、账号标识或私人资料。

## 3. 事务、隔离与权限

- 创建在同一事务内锁定并重新检查当前有效用户，取当时已完成昵称作为剧组内显示名，依次保存剧组、首名成员、`admin`岗位及成功审计；事务提交成功后才返回。后续个人昵称修改不自动改变剧组内显示名。
- 不同剧组可同名，标识使用UUID；`UNIQUE(crew_id,user_id)`防止重复成员。岗位和覆盖授权通过复合外键绑定同组成员；成员状态与退出时间成对，关联限制删除，审计不级联删除。
- `created_by`仅为来源，不参加读取授权。查询按本人当前有效成员身份过滤；`crew.read`明确拒绝时列表也隐藏。成员目录额外检查`member.read`。
- 所有成员有基础能力，兼任岗位取并集，业务权限明确拒绝优先。管理员默认只有组织管理能力，不自动获得剧本阅读或计划发布。组织权限不接受普通例外授权；未知权限/岗位不增加权限。
- 固定目录由代码定义并在迁移中保存快照，当前没有编辑目录的接口。目录列出未来业务能力不代表相应功能可用，例如`diane.use`仍受Diane未启用限制。
- 成功审计与创建共同提交。业务服务内拒绝或数据库失败后另开事务记录必要标识、动作、结果与请求标识，不复制原文；审计再次失败仅记脱敏运行日志。不宣称所有认证/格式/限流失败均已有完整持久审计。
- 会话与昵称前置检查复用账号模块；写入校验明确来源和CSRF。当前JSON接口按实际字节限制16KiB并禁缓存；未来文件上传需要独立的类型和大小策略。创建每IP/用户每窗口10次，读取120次，沿用认证缓存的限流窗口。

## 4. 前端流程与UI调整

登录并完善昵称后，从标题区或顶栏进入“选择或创建剧组”。选择后重新请求剧组详情确认访问，再在成员页加载真实目录；切换账号清除查询缓存并重新挂载工作台。剧组选择暂存组件内存，不进入持久存储；刷新后重新选择。

创建只提交名称、影片名称和说明，不自报创建者或管理员。前端同步锁防连点，不自动重试写请求。创建目前没有跨请求幂等凭证：提交响应未知时可能已经创建，页面阻止继续提交并引导查看列表；明确新建同名剧组仍可能产生不同对象，不能宣称严格只创建一次。

账号页取消标语，红块使用黑色`SS / Silencio Set`重复斜排，装饰文字对屏幕阅读器隐藏。桌面业务页左侧红块约占主体宽度四分之一，并覆盖接近整屏的主体高度，标题与内容在右侧；平板导航换行，手机上下布局。遵循[UI参考](../design/ui-reference-v1/README.md)，尚未通过真实浏览器截图验收。

任务、排期、资源仍显示明确开发占位，不伪造拍摄日期、人数或待办数量。布局预览不读取剧组业务，不代表已登录。本阶段未开放的岗位修改、末位管理员保护及邀请链路后续已实现；例外授权修改、移除/退出及责任交接仍未开放。
