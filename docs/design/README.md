# 软件设计基线

## 已确定的原则

1. 本地运行优先，使用模块化单体后端；API和Worker分进程运行。
2. 先完成普通页面与基础管理，再接入Diane。
3. PostgreSQL管理正式业务、审批、版本和任务状态；Redis用于验证码、会话、限流及必要缓存；RabbitMQ作为Celery消息Broker。
4. 文件保存到本地目录，由后端检查权限后访问，不使用分布式或云对象存储。
5. Diane使用LangGraph、LangChain及Qwen 3.7系列；Pi不作为运行核心。
6. 重要操作由授权人员确认，执行前重检权限、版本及冲突，重试和恢复需防止重复业务变更。

## 待展开设计

架构与模块、数据模型、接口、关键流程与异常、页面交互、非功能策略、设计权衡、需求追溯和测试验证。具体依赖版本在实际初始化时验证并锁定。

## 变更说明

此基线依据最新讨论，将此前云部署与OSS候选调整为本地方案，并按负责人要求保留RabbitMQ。注册使用邮箱验证码；具体登录凭证方式仍需在认证设计中明确。
