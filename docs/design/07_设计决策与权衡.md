# Silencio Set · 设计决策与权衡

版本：D0.1  
状态：已确认设计选择及适用边界；未据此宣称实现完成、性能达标或替代方案已完成对比测试。

## 1. 决策依据

需求基线为[需求分析V0.8](../requirements/01_Silencio_Set需求分析.md)及[后续补充范围](../requirements/README.md)。项目是个人开发的学生剧组前期准备平台，当前本地运行、不租服务器、不引入分布式存储。设计优先保证普通业务独立可用、数据正确和权限明确，再接入Diane。

本章说明选择、代价及何时重新评估，不是技术名词清单；未采用的方案不代表技术本身不可用。共享架构能力可支撑多项需求，需求编号表示关联依据，不表示原需求强制指定某个组件。

## 3. 重新评估条件

出现实际问题再考虑调整，而不是预先扩大项目范围：

- 同剧组写竞争在分类压测中成为瓶颈，再评估锁粒度；优化仍须通过同一套正确性及并发测试。
- 明确需要独立扩容或多机文件访问，再评估拆分服务或对象存储；当前不实施。
- 真实多人编辑反馈证明版本冲突频繁且影响使用，再评估差异比较及协同编辑，不提前增加实时协同。
- 跨文档知识查询出现明确需求，已有样本能够比较检索准确性、用量和延迟，再决定是否引入图谱或复杂检索。
- 框架或模型能力不满足业务，再对真实任务样本评估替代方案，涉及费用与数据发送范围变化须重新确认。

## 4. 决策变更规则

每次改变记录原ADR编号、改变原因、替代选择及代价、受影响需求和设计、所需验证及负责人确认。更新相关文档和版本，保留变更依据；不静默删除旧约束或将待评估选项写成既定架构。

本章不是需求追溯矩阵的替代；后续矩阵须逐项关联FR、BR、NFR及新增需求至设计、接口、数据和测试定位。已确认选择不等于已完成实现，待测试的性能及容量仍按需求7.4确定。
