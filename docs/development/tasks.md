# 筹备任务：实现与验证边界

当前实现任务创建、分页筛选、详情、调整/转交、开始、成果提交、通过/退回、取消和历次提交；总览已接入这些入口。任务责任检查已注册到成员退出/移除事务。通知消费及任务交接清单也已实现，见[通知说明](notifications-and-handover.md)。当前迁移头为 `0008_availability`，最新阶段见[档期说明](availability.md)。

尚未实现场戏关联及预约/安排交接；Diane未接入。真实PostgreSQL迁移与锁竞争、容器依赖联调、浏览器视觉及性能验收均待补，不能把下列模拟测试当作上述验收。

## 1. 核心代码与业务规则

- `tasks/models.py`：任务、协作关系、提交、幂等回执和任务变更事件；与后台任务的 `jobs/` 分开。
- `tasks/repository.py`：当前成员/权限、对象读取范围、状态机和事务；`TaskService`供HTTP及以后内部工具复用。
- `api/tasks.py`：登录、昵称、Origin/CSRF、频率及参数边界。
- `frontend/src/tasks/TaskBoard.tsx`：总览任务列表、详情、输入及明确确认；使用共享账号HTTP客户端。

负责人唯一，确认人唯一，可有最多20名协作人。导演、制片默认具备 `task.manage`，可查看全组任务、创建、调整、取消；管理员身份本身不获得这些业务权。普通成员仅能读本人发布、负责、协作或确认的任务。负责人具备 `task.work` 才能开始/提交，指定确认人具备 `task.review` 才能验收，管理权不代替二者。指派同时检查同组、在组、账号有效、读取及相应工作权限。未强制负责人和确认人必须是不同成员，现有需求没有这条限制。

| 当前状态 | 操作 | 结果 |
|---|---|---|
| 待处理 `pending` | 负责人开始 | 进行中 `in_progress` |
| 进行中 | 负责人提交成果 | 待确认 `pending_review`，新增递增编号提交 |
| 待确认 | 指定确认人通过 | 已完成 `completed`，当前提交 `accepted` |
| 待确认 | 指定确认人退回并说明原因 | 进行中，当前提交 `rejected`；重新提交新增记录 |
| 待处理/进行中 | 授权管理者调整基本信息、转交责任 | 保持状态，递增版本 |
| 任一未终结状态 | 授权管理者取消并说明原因 | 已取消 `cancelled`；当前待确认提交也标为 `cancelled` |

已完成和已取消不能继续修改。取消关闭提交由取消操作者记入 `reviewed_by/reviewed_at`，表示关闭经办人和时间，不构成指定确认人的验收决定；界面区分“因任务取消关闭”和“已退回”。

## 2. 接口与格式

前缀 `/api/v1/crews/{crew_id}/tasks`，JSON请求体上限16 KiB；日期为带时区ISO日期时间，页面输入/展示固定北京时间。截止时间创建时及明确修改时须晚于数据库当前时间；调整其他字段允许保留原逾期时间。

| 方法 | 相对路径 | 必填输入 / 主要结果 |
|---|---|---|
| POST | 空 | `title/owner_member_id/reviewer_member_id/due_at`；201任务 |
| GET | 空 | `page/page_size/status/owner_member_id/due_from/due_to`可选；200分页任务 |
| GET | `/{id}` | 200：`task/member_names/current_submission/submission_count` |
| PATCH | `/{id}` | `expected_lock_version`及至少一项基本信息调整；200任务 |
| POST | `/{id}/start` | `expected_lock_version`；200任务 |
| POST | `/{id}/submissions` | `completion_note/expected_lock_version`；200任务 |
| GET | `/{id}/submissions` | 分页；200按提交序号倒序的历史 |
| POST | `/{id}/reviews` | `submission_id/decision/expected_lock_version`；200任务 |
| POST | `/{id}/cancel` | `reason/expected_lock_version`；200任务 |

创建、提交、验收、取消要求 `Idempotency-Key` 请求头，值为UUID。开始、调整使用成员/任务当前版本及明确读取处理未知结果，不自动重放。

标题1—100字，说明选填最多3000字，完成说明1—2000字，验收说明最多500字且退回必填，取消原因1—500字。说明字段可换行；标题与取消原因单行。字段去首尾空白、拒绝不支持控制字符，长度按Unicode字符检查。成员ID为UUID，协作集合最多20个且唯一。`scene_id`目前只能省略或为null；其他值422，不伪造场戏记录。

版本为1—2,147,483,647严格整数，拒绝布尔和字符串。PATCH不接受状态，不接受清空负责人/确认人/截止时间；说明可明确设null，协作可设空数组。状态、负责人等过滤始终与当前访问范围取交集，不能借筛选扩大权限。分页1—100000，页大小1—100，页面固定20；列表按截止时间及UUID稳定排序。

任务输出包括基本字段、成员引用、协作集合、状态、新版本、时间及 `allowed_actions`；后者只是当前操作提示。详情另返回上述人员的剧组显示名映射，不含邮箱/账号ID。当前提交是最近一次记录，历史另分页，避免无限响应。前端只接受白名单字段并隐藏读取失败后的旧详情及历史。

## 3. 事务、幂等与离组

写操作统一顺序：操作者账号共享锁 → 剧组协调锁 → 锁后重查在组身份/权限 → 任务行锁。角色修改、邀请接受、成员离组使用相同剧组协调锁。读接口按当前身份和对象范围查询，不串行占用剧组写锁。

每次成功变化将任务、提交处理、角色关联、成功审计、任务变更事件和适用的幂等回执共同提交。数据库复合外键强制任务与成员同组；每任务提交编号唯一，部分唯一索引保证最多一个 `pending` 提交。复合外键显式命名，避免同表重名。

回执以剧组、用户和键摘要唯一，内容摘要绑定操作、目标和规范化请求；同键异内容409 `IDEMPOTENCY_KEY_REUSED`。同键同内容在重查当前读取及操作资格后、检查旧版本之前返回原成功快照，不新增提交、审计或事件。原快照 `allowed_actions`清空，后续操作先GET最新状态；当前失权不能借回执恢复访问。回执暂无自动清理策略，不承诺任意保留周期。

开始/调整未知结果必须先读取；要求幂等键的操作未知时，页面冻结原内容和键，允许用户明确恢复同一次操作，无自动请求重放。关闭/刷新后内存恢复上下文丢失，应先核对任务和提交历史，不能直接重新创建。

成员仍是任何非已完成/已取消任务的负责人或确认人时，退出/移除409 `MEMBER_HAS_RESPONSIBILITIES`。查询失败中止事务。待处理/进行中可由有权人员调整负责人/确认人；待确认先验收或取消。仅协作、发布历史不阻断离组，历史引用保留。任务交接清单已接入，其他业务责任继续随模块实现。

## 4. 通知及其他限制

`task_change_events`保存同事务通知意图，按任务与版本唯一，包含实际操作者及发布人、新旧负责人/确认人和协作人的成员ID集合。站内消费者会重查当前在组、入组时间与对象读取权限，再共同提交通知、接收人及`dispatched`标记；格式错误事件隔离为`failed`。它不交给邮件Worker，实际运行与回执规则见[通知说明](notifications-and-handover.md)。

目前粗粒度剧组写锁优先保障离组、指派与授权的一致性；未测吞吐，不声明高QPS指标。全局账号禁用功能尚未实现，未来也须加入组织与任务并发协调。创建/提交/验收正文不进入普通日志，审计只记录必要状态、版本及指派差异。

后端测试覆盖状态/版本/指定人权限、同组可见范围、资格校验、旧提交拒绝、重提交编号、取消关闭、回执恢复和冲突、审计/事件/提交事务、责任阻断、应用注册以及离线迁移约束。前端覆盖实际HTTP契约、跨组响应拒绝、创建未知结果同键恢复、验收退回必填、旧版本读取后确认和失权隐藏历史。

测试不连接真实PostgreSQL、Redis或RabbitMQ，不调用Qwen；原有测试仍使用fakeredis与回环SMTP。离线生成SQL及约束检查不证明数据库实际建表或锁竞争成功。真实迁移、并发提交/取消、邮件/通知投递、浏览器和压测仍待完成。
