# 人物与演员绑定

本批接入人工选角及排期联动，不调用模型。迁移头为`0021_casting`，仅完成离线SQL验证，尚未执行真实数据库迁移。

## 业务规则

- 同一剧本中的同名人物共用一位演员，跨剧本互不影响；一位演员允许饰演多个人物。系统不自动推断人物别名，同名但不同人物需使用不同名称。替身、群演人数及同一人物多演员分段出演尚未建模。
- 人物名称来自已有场戏记录。列表合并当前工作版本各拆解中登记的人物与历史绑定，按名称分页，每页20项；历史名称会明确标记，允许解绑。登记人物不要求先分配演员，正式排期发布时必须落实。
- 仅选择本剧组账号有效、仍在组且具有演员岗位的成员；绑定记录包含入组时间，离组后重入不会恢复旧绑定。演员姓名为显示快照，当前有效绑定展示最新在组姓名。
- 导演按`script.read + scene.review + member.read`维护；制片按`plan.edit + member.read`维护。只读要求`script.read + scene.read + member.read`，或`plan.edit + member.read`。编剧的`scene.edit`、管理员身份均不等于选角权。演员无需直接读取全剧本或选角表。
- 绑定不会自动添加排期参与人、改写剧本、确认场戏、发送邮件或触发模型。后台也不因选角权限授予剧本正文编辑权限。

## 存储与并发

新增`character_castings`：同剧组的剧本、人物名称、成员ID、入组时间、演员名快照、修改成员及时间；`script_id + character_name`唯一，同剧组复合外键禁止跨组引用。

复用`Script.lock_version`：切换工作版本或其他剧本级写入会与选角产生版本冲突。绑定、解绑同时增加该版本，避免另设一个几乎相同的锁聚合；剧本正文版本的锁仍保持独立。解绑删除当前关联，成功审计及幂等回执保留结果，正式排期和通告快照不变。

写入与成员组织管理共用剧组协调锁，校验当前权限、成员入组身份、名称归属及乐观版本。复用`creative_action_receipts`，摘要包含动作、剧本ID及完整请求；当前操作者权限检查后、版本冲突判断前重放原结果。同键异内容或重入身份拒绝重放。绑定、剧本锁、受影响安排标记、审计与回执在同一SQL事务提交。

## 接口

均位于`/api/v1/crews/{crew_id}`，正常读取200，写入200。绑定读写复用创作服务限流：读取120次／分钟、写入10次／分钟（账号及IP），会话、权限仍逐次检查。

| 方法与路径 | 输入 | 输出 |
|---|---|---|
| GET `/casting-scripts` | `page` | 剧本ID与标题分页，不返回正文 |
| GET `/scripts/{id}/casting` | `page` | 剧本锁、人物分页、是否在工作稿、绑定成员／入组时间／显示名与状态 |
| GET `/scripts/{id}/casting/actors` | `page` | 可选演员ID、显示名、入组时间分页 |
| PATCH `/scripts/{id}/casting` | `expected_lock_version, character_name, member_id, membership_joined_at`；CSRF及UUID幂等键 | 本次人物绑定及新剧本锁 |

解绑时成员ID与入组时间同时为`null`。绑定时二者必填，入组时间必须带时区。空白人物名称、未知字段及不完整身份为422；当前无权限403；剧本或人物不属于该剧组404；版本／身份变化、演员不可用、幂等键误用409。数据库故障返回经过脱敏的503。

## 排期与通告

预检读取已登记人物、对应剧本的当前绑定、演员有效性及入组时间，检查：

| 阻塞码 | 条件 |
|---|---|
| `CHARACTER_UNCAST` | 人物未绑定演员 |
| `CAST_MEMBER_INVALID` | 演员已离组、重入、账号不可用或不再有演员岗位 |
| `CAST_MEMBER_UNSCHEDULED` | 有效演员未以相同入组身份加入本场参与人 |

演员加入参与人后仍需通过已有的档期、重叠及转场检查。仅覆盖已录入人物，未登记的人物仍需人工核对。

预检指纹包含人物绑定状态、成员身份及绑定修改时间，发布在同一剧组锁下重新采集比较。新发布安排在`publication_snapshot.items[].characters`保留当时人物与演员，后续改绑不回写。

绑定或解绑只标记同剧本、含该人物且尚未结束的当前正式排期为`casting_changed`；演员岗位增删按其已有绑定标记`casting_role_changed`。复用来源变更链路，将相关当前通告标记待复核。既有排期／通告知悉检查会拒绝对已失效依据新增确认。已结束安排保留历史记录，不由本次操作追改。

## 前端与验证

导演在剧本资料中打开“查看人物与演员”；制片在排期页打开“安排人物与演员”，选择剧本后操作。候选演员仅在选择器打开时请求。确认框展示人物与所选姓名；结果未知保留请求与幂等键，只允许手动原请求重试，选角剧本切换暂时禁用。已知冲突刷新依据后须重新选择；成功使当前剧组查询失效，更新选角、排期、通告、通知与总览。读取失败隐藏缓存中的私有绑定内容。

后端定向覆盖权限、同组查询、入组变化、幂等、事务提交失败、预检组合、精确影响范围、岗位变更及离线迁移；前端覆盖确认、权限、冲突、未知结果重试及页面入口。未完成真实PostgreSQL联调、浏览器视觉验收和压测；不将这些测试当作容量或上线证明。
