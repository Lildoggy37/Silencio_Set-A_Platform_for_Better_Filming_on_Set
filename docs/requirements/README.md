# 需求文档快照

此目录保存课程需求分析V0.8及配套记录的本地快照，来自项目文档目录。原始参考范文、帖子截图和私人剧本不纳入仓库。

V0.8之后已确认的补充范围：邮箱验证码注册、邮箱与密码日常登录、通告单正式纳入、勘景照片供导演查看、现场场记排除。软件设计应记录这些变更并补充需求编号及验收对应，不假称它们已完整包含在V0.8中。

人工核实文档区分负责人提供的反馈归纳与尚未附入的原始证据，不视为完成产品测试。

## 设计阶段需求补充

`SUP-01 首次登录补全个人信息`：来源为负责人本轮明确提出“登录后需要补充个人信息，比如昵称”。设计采用邮箱验证并设置密码完成注册，首次登录后填写昵称再进入剧组业务；昵称去除首尾空白后1—30字，无需全平台唯一，不新增真实姓名、手机号或学校等必填资料。该项补充首次填写时机，延续NFR-09的最小信息原则，不修改V0.8原始快照。

验收：未补全账号登录后进入资料页，直接调用剧组业务接口亦被拒绝；有效昵称保存后可正常进入，重新登录不重复要求填写；空白、超长昵称拒绝；多窗口修改不静默覆盖；从邀请入口进入仍须补全且接受时重检邀请。对应设计为接口文档5.1、用户表资料完成字段及关键流程2.3。

### SUP-02 邮箱注册与密码登录

来源：负责人在技术选型中明确要求邮箱注册发送验证码，后续接口审阅确认邮箱与密码日常登录。本项补充FR-01的账号入口，不改动原FR编号。

要求：邮箱验证成功后持短期注册凭证设置密码；注册不自动登录。日常邮箱密码登录，采用服务端会话，退出使当前会话失效。验证码单次使用、重发旧码失效，验证及登录失败受限流控制；具体参数实施前确定。

验收AC-SUP-02：验证成功才能创建有效账号；并发或重复注册不创建第二个账号或覆盖密码；旧验证码、过期凭证及错误密码拒绝；退出后不能继续访问业务；认证依赖故障不放行；密码、验证码和会话密钥不进入普通日志。对应05接口第5节、03数据第2节和04流程第2节。

### SUP-03 通告单生成与发布

来源：负责人明确要求纳入通告单生成，后续流程和接口审阅确认审核、版本、知悉与PDF导出；UI参考V1确认发送通告为排期内流程。本项与FR-07、08联动，不另设一级导航。

要求：按确定的已发布计划版本和拍摄日期生成通告草稿，补充集合信息等说明，经审核发布，通知有权接收的剧组成员并记录知悉；已发布内容修改产生新版本。计划变化触发旧通告复核或撤回。本阶段通告导出PDF；DOCX与PDF剧本输入范围不变。

验收AC-SUP-03：来源无效、审核未完成或版本冲突时拒绝发布；修改已审核内容须重新审核；同计划同日对象不重复，跨午夜按上海时区场次开始日归属；来源变化后不能继续将旧通告显示为当前有效；新版本重新确认，历史回执保留；重复发布不重复产生业务结果；导出绑定具体版本，失败不返回旧PDF冒充成功。对应03数据第19—20节、04流程第6节、05接口第17—18节及UI发送通告参考。

### SUP-04 场地勘景照片

来源：负责人明确勘景可直接将图片提供给导演，后续审阅落实为场地关联照片及授权查看，不增加独立勘景审批或AI图片分析。

要求：上传照片后关联同剧组场地，导演及获授权成员经鉴权查看，文件保存在私有目录。后续审阅确认设计初值：静态JPEG／PNG／WebP，单张10MiB、2500万像素，单场地最多20张，说明500字；规范方向并清理EXIF定位，不默认AI分析。详见D03第12.2节和D05第26.3节，处理资源及性能仍待验证。

验收AC-SUP-04：拒绝跨剧组或无权使用的文件关联及访问；照片正确关联对应场地；图片失败局部提示，不用其他照片替代，不影响仍可读取的场地文字；不默认向模型发送照片。对应03数据第6、12.2节，05接口第8、13节及06非功能FB-10。

SUP-01的上文验收统一记为AC-SUP-01。上述补充为已确认讨论的规范化记录，不表示产品已通过验收。现场场记排除、图像生成暂缓、本地运行及不租服务器作为范围约束，不编号为待开发功能；详细映射见[需求追溯矩阵](../design/08_需求追溯矩阵.md)。
