# 场地资料与勘景照片

场地详情、勘景照片上传／查看／说明编辑／移除已接通前后端，迁移头`0020_locations`。入口在资源页的场地详情中；设备、道具和耗材不开放此模块。导演及当前剧组具有resource.read的成员可查看，制片或具备当前场地维护范围的resource.manage成员可修改；管理员或审批人身份不自动取得维护权。

## 接口

统一前缀`/api/v1/crews/{crew_id}/locations/{resource_id}`。写请求沿用会话、CSRF、UUID Idempotency-Key及当前资源锁版本；读取与图片流也需当前有效账号、剧组身份和resource.read。

| 方法与路径 | 契约 |
|---|---|
| GET 空后缀 | 场地资料、有效照片、resource_lock_version与allowed_actions |
| PATCH 空后缀 | expected_lock_version及address、access_instructions、shooting_constraints中的至少一项；200 |
| POST /photos | multipart：file、expected_lock_version、可选description；处理并关联成功201 |
| PATCH /photos/{photo_id} | expected_lock_version、description，可空；200 |
| POST /photos/{photo_id}/remove | expected_lock_version；解除关联并使内容链接失效，200 |
| GET /photos/{photo_id}/content | variant=preview默认小图，或full处理后大图；直接返回私有图片流 |

地址最多300字，单行；进入方式最多1000字，拍摄限制最多2000字，可多行；空白转为空值，PATCH未提供字段不覆盖已有内容。照片说明最多500字。所有资料／照片变化检查并递增resources.lock_version，不另建照片集合锁版本。

查询按所属剧组、location资源类型及有效照片关联检查，不能仅凭照片ID或旧链接访问。未找到、跨组、类型不符或照片已移除时隐藏404。图片URL不含令牌、邮箱或磁盘路径；响应no-store、nosniff、CORP same-origin，展示类型由处理后的实际格式决定。

## 规范化处理

- 原始单文件最多10×1024×1024字节，解码像素最多25000000；仅JPEG、PNG、静态WebP。文件实际签名及解码结果决定格式，客户端文件名和MIME不用于决定类型。
- SVG、GIF、HEIC等格式返回415；PNG／WebP动图返回415；损坏、空文件、像素超限或解码超时返回422；字节超限或处理后大图超过10MiB返回413。
- 解码后按EXIF方向校正，以全新的像素对象重新编码，清除源EXIF、GPS、XMP、ICC、注释等元数据。不执行脚本，不访问外部链接，不将照片交给模型。
- 保存校正后的大图，JPEG／WebP重新编码质量90，PNG保留透明像素；大图不主动缩小尺寸。另生成最长边1280像素的静态WebP预览图（质量85），相册先加载预览，按需查看大图。并非逐字节保留原件，也不宣称色彩管理或无损还原。
- 原始临时上传在请求结束关闭，只把规范化大图和预览图写入业务私有目录，不提供未经清理原件下载。照片中的可见定位文字或用户主动填写的地址／说明不属于可移除的EXIF元数据。

处理使用Pillow 13.0.0，API直接声明Pillow依赖并同步锁文件，未升级已有版本。方向处理与解码接口参考[Pillow ImageOps](https://pillow.readthedocs.io/en/stable/reference/ImageOps.html#PIL.ImageOps.exif_transpose)、[Image参考](https://pillow.readthedocs.io/en/stable/reference/Image.html)。解码在独立Python进程中执行，最长30秒，每个API进程同时最多1项；没有OS级内存硬配额或全局排队总量保证，内存和处理性能仍待实测。

## 数据、权限与并发

新增location_details与location_photos，通过同剧组复合外键关联resources，用户外键记录上传及移除人员。照片保存实际格式、尺寸、字节数、处理后摘要、私有大图／预览键和时间；DTO不返回存储键、摘要或上传者私有信息。有效照片有筛选索引，像素、大小及移除人／移除时间配对有数据库约束。location类型限制由业务服务检查，资源类型不能通过普通编辑改变。

每场地最多20张有效照片。上传前短事务校验维护权、资源版本、幂等回执及数量，然后释放协调锁处理图片；最终事务重新检查这些条件，避免处理期间他人新增照片或撤销权限。场地资料、照片元数据、资源版本、审计及成功回执共同提交。维护范围需匹配成员本次入组时间，角色的明确拒绝仍生效。

沿用ResourceReceipt，动作命名空间为location.*；摘要绑定资源／照片、动作、预期资源版本、说明及原始文件SHA-256。同键重试恢复原结果，不重复处理或挂接；同键改动、入组身份变化拒绝重放。最终提交失败不返回成功。

移除仅软删除关联并增加资源版本，历史元数据及私有文件保留，不开放任意磁盘删除。已经下载的照片无法远程收回。文件写入与数据库不是一个原子事务；提交结果未知、最终权限变化或并发同键可能留下未引用的规范化文件，当前没有自动垃圾回收或磁盘总配额，后续清理须核对数据库引用，不能误删已关联文件。

## 页面与实现取舍

场地详情展示地址、进入方式、限制及图片网格；上传、修改和移除均先核对再明确提交。结果不明时冻结原文件和操作键，手动原请求重试；已知冲突可读取最新场地并保留输入，权限、照片或数量不再允许时禁用原操作。刷新失权会隐藏旧资料与图片，单张预览失败可局部重试，不伪装成空相册。

上传后有权成员可在同一场地直接查看；本批没有导演私人消息、站内照片推送、外部分享公开链接或AI图片分析。通用资源维护范围授权入口仍待完善，现有制片岗位可直接使用，既有范围授权由服务严格检查。场地资料变化不覆盖正式排期冻结快照，本批未新增勘景变化的自动影响提醒。

原设计采用通用files上传再关联file_id。本批使用绑定场地的上传与关联一步完成，元数据内聚在location_photos中，未实现通用文件中心，也不返回虚构处理进度。规范化成功后才201；失败不创建可见照片，照片类型、大小、数量、版本及权限边界保持。

私有文件默认保存`<仓库>/runtime/private-location-photos`，可用LOCATION_PHOTO_STORAGE_ROOT指定目录，不挂载到静态资源服务，不读取或改写实际.env。共享PrivateFileStorage只负责服务器键与路径边界；剧本原件和勘景照片使用各自私有目录及业务鉴权。
