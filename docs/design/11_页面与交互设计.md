# Silencio Set · 页面与交互设计

版本：D0.4  
状态：账号、剧组/成员、任务、通知、档期及资源登记／预约页面已接入；资源借还／库存／图片、拍摄计划、创作资料及Diane待实现。真实浏览器视觉及可用性验收尚未完成。

## 1. 设计依据与导航

视觉沿用[UI参考V1](ui-reference-v1/README.md)的国际主义网格、红黑暖白、方角、纯色和细分隔线，不新增侧栏、渐变、投影或彩色状态胶囊。本章补行为，不重新生成视觉；参考图中的人数、日期和状态均为示例，不能硬编码为真实结果。

剧组内一级导航为总览、排期、资源、成员。顶部项目资料入口进入剧本、场戏和分镜；通知入口进入本人通知；个人菜单提供资料设置、我的剧组及退出。任务列表从总览“全部任务”进入，通告从排期进入。剧组切换前检查未保存修改，切换后清理原剧组数据和选择，不将其他组结果短暂显示为当前内容。

不同岗位按钮依据D10有效权限和对象责任显示，管理员不自动显示业务发布或创作资料入口。空结果、未加载、请求失败和无权限必须区分；前端隐藏按钮不替代后端鉴权。权限已变化的旧页面在操作被拒绝时刷新授权并停止提交，不继续展示敏感旧内容。

## 2. 账号、个人资料与我的剧组

### 2.1 正常路径

邮箱申请验证码→验证取得短期注册凭证→设置密码完成注册→邮箱密码登录→首次补昵称→我的剧组。昵称仅1—30字、不唯一；不增加头像、真实姓名、学校或手机号必填。填写成功再进入业务，重新登录不重复要求已完成账号填写。

我的剧组展示本人仍有权进入的剧组，并提供创建入口；无剧组时显示说明和创建／处理有效邀请的路径，不伪装已有拍摄安排。邀请链接登录后先补资料，再明确接受；后端重检邮箱、期限及状态，不自动加入、不延长有效期。

### 2.2 空状态与错误

验证码显示受理及适用发送状态，不宣称已到收件箱；错误或过期提供重新申请入口，受重发限制。登录失败统一提示，Redis不可用显示认证暂不可用。资料错误定位字段，版本冲突保留输入并重新读取，不自动覆盖。会话失效返回登录，未保存敏感内容不放URL或持久浏览器存储；重新登录不自动重放修改请求。

移动端保持单列，可完成注册、昵称与邀请处理；表单有标签、错误文字及键盘可达操作。

## 3. 总览与任务

总览只显示当前权限范围的待完成、待确认数量，优先展示少量待办。制片／导演可按权限查看筹备工作，普通成员仅本人相关范围；局部资源或照片失败不阻断任务入口。无任务与筛选无结果分别提示，不将错误填为0。

下一拍摄日依据可访问的正式安排；集合信息来自有效已发布通告，置于左侧红区中段。无已发布安排时显示尚无正式排期，不编造日期；已有计划但无有效通告时明确集合待定，不把草稿集合时间当正式信息。

“全部任务”进入列表，详情展示负责人、确认人、协作人、截止时间、状态、来源场戏及提交历史。创建分配需`task.manage`；负责人开始及提交，指定确认人验收；取消展示原因和影响。待审及终态不开放任意编辑，退回展示原因并允许负责人重新提交。

保存、提交、验收期间显示处理状态；响应不明查询或原键恢复，不生成新任务。版本冲突保留输入，提示刷新核对，不自动重提。手机必须支持查看本人任务、开始、填写完成说明及提交；已授权验收也保持可达，不用桌面宽表遮挡关键动作。

## 4. 排期、档期与冲突

排期区分草稿与已发布，不把预检结果当作正式安排。导演按权限查看，制片编辑与发布；工作人员及演员查看本人相关安排。编辑场次显示来源修订、时间、参与成员、实际场地、资源及转场准备，不用剧情地点代替落实场地。

“冲突检查”展示阻断项与未知项，支持定位相关场次／对象；阻断项提供处理入口，不提供强制忽略。未知档期逐项展示成员及确切区间，默认不勾选，确认集合与后端预检标记绑定。依据变化或原发布版本变化时要求重新检查，保留草稿不静默覆盖。

发布前展示版本差异及影响，只有具备发布权限且规则满足时提交。结果区分已发布、通知待投递及需要复核通告，失败不显示半成功。无排期显示建立草稿入口或无相关安排说明，无权限者不提供创建按钮。

本人档期从个人入口或成员页“我的档期”进入；查看他人详情只显示获授权的汇总。本人以区间编辑及范围替换保存，未知与明确可用区分，不允许管理员代改。更新影响正式安排时说明已保存真实档期、相关计划需要复核，不强迫维持旧可用状态。

当前从成员页或排期页进入“我的档期／剧组档期”。本人草稿先核对范围和清除含义，再明确保存；读取新范围明确会替换草稿，冲突/未知结果另有保留草稿的重新读取入口。授权剧组视图只读；未登记明确标为未知。拍摄计划复核尚未实现，不能声称当前已复核正式安排，见[实现说明](../development/availability.md)。

手机优先展示按时间排序的本人场次和完整日期，跨午夜明确次日结束；本人档期支持单列输入。复杂整份计划编排以桌面为主，手机不通过缩小整张桌面图替代可读页面。

## 5. 排期内发送通告

从已发布排期进入，页面左侧为通告预览、右侧为接收选择，移动端上下排列。未发布草稿不能直接生成有效发送结果。展示来源计划、日期、集合、场次、备注及通告版本；预览不是可跳过审核的发布凭证。

来源当日参与者默认选中且不可取消，其他在组人员可选；必选原因有文字提示。成员变化或保存冲突就地说明，不静默剔除接收人。内容与集合共同送审，待审不可改，退回展示原因恢复草稿；已审核修改使审核失效，已发布修改及新增接收人走新版本。

“确认发送”仅在有效审核且具备发布权限时执行；未审核时提供保存／送审动作，不让截图中的发送按钮绕过流程。审核发布可同人但权限分别校验。发布成功、等待投递、成员未读／未知悉分开显示；原投递失败补投不重复发布，旧版回执不迁移到新版。

导出PDF异步显示真实阶段，失败保留网页版及受控重试；无权限者不显示导出操作，不能取旧PDF冒充新版。来源过期显示待复核、替代或撤回，提供当前安排入口，不能继续确认失效版本为当前安排。

## 6. 场地、资源与借还

首期资源页已提供目录、分页详情、登记／维护、负责人及审批授权、北京时间余量查询、可见预约与申请／决定／取消。提交前核对，未知结果冻结原内容并明确原键重试，版本冲突先读取并保留草稿。授权选项默认不勾选，说明替换既有拒绝与其他资源范围的影响。离组资源清单可跳转资源详情；查询失败不显示无责任。其余本节行为为后续目标，见[资源实现边界](../development/resources-and-reservations.md)。

资源页沿用全部、待审批、借还等次级入口，按权限展示目录与操作。普通成员查看目录和本人申请；制片或授权人员维护资料；只有具备审批权限且是资源负责人者看到可执行批准入口。查看余量明确为查询时结果，不承诺预占。

预约表单展示时段、数量及来源场戏，待审批不算落实。审批前展示当前资源与余量，冲突定位数量及区间，详情按权限过滤。变更申请期间原预约仍有效，禁止页面直接覆盖已批准数据。

借还经办展示预约数量、累计借出、未归还和预计归还时间，支持分次归还，停用或过期仍允许合法归还。耗材以流水登记而非编辑数字直接覆盖；失败保留表单，重复点击不重复记账。

场地照片与文字关联展示，点击由后端鉴权，失败局部占位，不替换他处照片，不默认发送模型。没有照片显示暂无勘景照片，不影响已有场地说明；资源为空仅有权者见新增入口。手机可查看资源、场地及照片、查询本人预约，实际开放的经办动作以可读单列表单承载。

## 7. 成员与权限

成员列表显示昵称、岗位及可访问业务状态，基本目录不暴露私人邮箱或联系方式。待办、通告及档期详情仅显示用户有权查看的范围，不能因参考图出现某列就全组公开。选择他人可查看授权详情，“查看档期”不等于代编辑。

管理员可邀请、查看邀请记录、调整岗位与例外业务权；界面明确组织授权不等于业务执行。修改前展示差异，移除或退出先展示任务及安排交接，末位管理员操作阻止并说明。重新加入不自动恢复旧权，不能借前端缓存继续操作。

无邀请记录显示空状态，过期及撤销显示实际状态。并发授权冲突保留选择并刷新成员版本，不自动覆盖。手机列表折为成员摘要与详情，邀请／授权表单按权限可达，敏感差异确认不隐藏于横向溢出区。

## 8. 项目资料：剧本、场戏与分镜

顶部项目资料入口按权限进入剧本版本，上传DOCX／文本PDF／TXT或粘贴。异步解析展示真实阶段，失败提供替代格式或粘贴，扫描PDF不声称OCR成功。待检查正文可核对修正，确认后冻结；确认与切换工作稿分开，历史来源保持可见。

场戏从确定剧本版本创建整份拆解，明确新旧场戏映射与原文引用；文字分镜按来源修订编辑有序镜头。仅草稿可修改，待审只读；退回显示原因，由有编辑权限者点击“重新编辑”后恢复草稿，已确认修改创建新版，不提供解锁覆盖按钮。

无资料区分暂无版本与无访问权；版本竞争保留输入并让用户核对。正文和模型文本按安全文本或受限格式渲染，不执行脚本。桌面优先承担正文核对、拆解及分镜整份编辑，手机保留有权限的资料阅读和状态查看，复杂编辑不作为首期移动验收要求。

## 9. 通知、Diane与操作提案

通知入口仅列本人通知，打开详情和明确知悉分开；版本失效提示当前来源，不能替成员确认。回执查看按业务责任授权，投递失败不回滚已成功发布事项。手机可读完整通知及确认按钮，不以悬停提供必要信息。

Diane未启用时不显示为可用入口；启用后本组本人对话私有，显示排队、执行、澄清、待确认及终态。退出页面不丢后端运行结果，回来按ID查询，不因刷新重发用户请求。失败提供普通页面或人工草稿入口，不影响基础业务。

提案以独立详情展示实际变更、目标与来源、影响、冲突和确认／拒绝，不能只在聊天里提供无对象的确认按钮。他人仅凭业务授权查看必要提案，不开放整个对话，具体分发契约仍待补。接受返回202显示已确认等待执行，不显示全部完成；执行结果、失败及已完成部分以数据库为准。耗时和token展示完整性，未知不填0；取消不暗示已提交业务撤销。

## 10. 公共交互、兼容与验证

| 情形 | 统一交互 |
|---|---|
| 未保存离开 | 离页或切组前提醒，允许返回继续；不将私密内容默认持久存浏览器 |
| 加载与失败 | 加载不显示假空数据，失败不替换为统计0，局部失败局部处理 |
| 版本冲突 | 保留本地输入，显示需要刷新核对，不自动覆盖或循环提交 |
| 响应不明 | 标明正在核实，查询或原幂等键恢复，不换键盲目再创建 |
| 权限／会话变化 | 停止敏感显示及提交，重新验证或登录，不自动重放写请求 |
| 旧内容 | 明确版本、有效性及更新时间，不将缓存当正式批准依据 |
| 表单与状态 | 标签、错误文字、键盘操作及必要符号俱全，不只靠红色或悬停 |

按NFR-07在固定Chrome、Edge版本和390像素宽度验证，一级入口可通过紧凑导航重排但不改变四项结构；表单和关键操作可达，不裁切正文和确认动作。按NFR-06真实试用验证入口可发现性及5分钟任务，UI参考图不作为已通过证据。

本章补齐交互规则层，关联FR-01—12、SUP-01—04及NFR-03、05—07、09—11；测试归入D09各业务端到端与专项组。路由、组件、尺寸、移动细节和可执行页面仍需实施验证，不能据此关闭实现与测试缺口。

本轮状态细化：影响分析pending／failed不得显示全部就绪，已读通知不解除问题；通告送审及发布检查集合必填、300／500／2000字限制及不晚于首场，网页PDF同版本；勘景上传明确提示静态JPEG／PNG／WebP、10MiB及2500万像素上限，每场地20张、说明500字，失败局部提示且不默认模型分析。数值为设计初值，不代表图片处理已完成压测。
