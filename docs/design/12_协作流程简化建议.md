# 协作流程简化建议

状态：用户已确认，本轮已实现。迁移为 `0025_workflow_policies`。以下流程更新替代旧文档中对应的强制逐级审批要求；Diane 仍未启用，其重要写操作只保留设计约束。

## 问题

当前主要服务学生剧组，成员少、经常兼任岗位。任务完成需要验收，场戏与分镜需要送审，通告要送审、审核再发布，资源负责人还需要另行授权。多处普通写入又有“核对—确认提交”两步。同一个人可能连续切换身份完成自己的操作，真正需要现场确认的事项反而容易积压。

应区分三件事。输入与冲突校验由系统完成，涉及他人责任和稀缺资源的决定由责任人确认，普通保存一次提交即可。

## 已实现流程

| 场景 | 原流程 | 当前流程 |
|---|---|---|
| 普通筹备任务 | 开始、提交成果、指定人验收 | 新任务默认由负责人直接完成并填写简短结果。重要交付可开启“需要验收”，保留退回与再次提交 |
| 场戏与文字分镜 | 编辑、送审、审核 | 导演可直接确认自己的稿件，其他成员提交的稿件由导演一次确认。保留草稿、确认稿及来源版本 |
| 日常设备、道具预约 | 申请、负责人审批 | 资源负责人可设置“无冲突即可预约”。提交时检查库存、时间重叠和访问权限，成功后立即占用容量 |
| 贵重设备、借来的器材、受限场地 | 申请、负责人审批 | 保留一次负责人确认。负责人在授权范围内为自己安排资源时可直接确认，避免自我审批 |
| 正式拍摄排期 | 保存、手动预检、核对、发布 | 草稿直接保存。点击发布时同步预检，集中显示冲突与未知档期，再进行一次发布确认 |
| 每日通告 | 生成、编辑、送审、审核、发布 | 从有效排期生成后，由制片预览并发布。内容由别人代编时，制片预览即完成最终确认 |
| 普通通知 | 已读、知悉 | 普通更新只需已读。正式拍摄通告保留本人知悉，回执用于确认成员已获悉安排 |
| 权限、成员退出、正式排期撤回 | 多处确认及责任检查 | 保留关键确认，集中展示实际影响和待交接责任 |
| Agent 重要写操作 | 人工确认后执行受控工具 | 每次展示具体改动，由用户确认一次。同一次已确认操作复用业务校验，避免再次要求相同审批 |

## 页面表现

- 普通保存、任务开始、填写预约申请采用一次提交。成功后返回原列表或详情，提供明确反馈。
- 待确认页面仅汇总需要当前用户处理的责任事项，优先显示原因和下一步操作。
- 资源显示“无冲突即可预约”或“需负责人确认”，提交前即可预期结果。
- 来源变化时标记受影响内容，由负责人决定是否沿用或修订。正式记录保留发布时的内容。

## 实施范围

本轮调整任务完成、资源预约、本人创作稿确认、排期保存及发布、通告保存及预览发布。沿用原角色与权限代码；本人创作稿直接确认要求同时具有编辑与审核能力，不能确认他人的草稿。

任务增加是否需要验收的设置，资源增加预约策略。已有任务与资源沿用原流程，新建页面默认普通任务无需验收、资源无冲突直接预约，均可在表单中更改。旧 API 调用未传新字段时，任务由是否提供确认人推断，资源仍默认人工确认；历史记录和已在途审批不自动转换。同步更新需求基线、权限说明、状态转换与相关验收项。

业务校验继续覆盖成员身份、资源容量、版本及重复提交。取消跨人审批的场景同样需要保留操作者、结果和时间记录。

## 评估

以“普通任务一次完成、普通资源一次预约、通告一次预览发布”为操作目标。试用时记录从提交到完成的等待时长、需要制片处理的事项数量，以及错误发布或资源冲突的实际情况，再判断是否需要提高某类对象的确认要求。

## 字段、接口与状态差异

| 对象 | 字段或入口 | 规则 |
|---|---|---|
| 任务 | `requires_review` 布尔；创建、修改及详情 DTO | 普通任务可从待处理或进行中直接提交结果并完成；重要任务继续开始、提交、验收。直接完成的成果状态为 `completed`，审核人和审核时间为空，不伪造自我验收 |
| 资源 | `approval_policy: manual / automatic`；创建、修改及详情 DTO | 预约策略仅可由有资源维护权者修改；改变策略不转换已有待审批申请 |
| 预约 | `confirmation_mode: manual / automatic` 只读 | 自动确认在事务中检查时段峰值容量；与已有人工确认共用锁及容量约束。授权负责人本人申请可直接确认，并保留实际审核人；策略自动确认不伪造审核人 |
| 场戏／分镜稿 | `POST .../{id}/confirm`；详情增加 `created_by` | 仅作者且具备编辑、审核能力可确认自己的非空草稿；校验来源与关联，保存确认快照。其他人草稿仍提交后审核 |
| 通告 | 复用 `POST /call-sheet-versions/{id}/publish` | 草稿或待审核稿发布者同时须有审核和发布能力，预览确认与发布同事务留痕；旧已审核稿仍可发布。发布时检查集合资料、接收人、有效来源及当前版本指针 |
| 排期 | 复用现有保存、预检及发布接口 | 普通保存直接提交；发布按钮先同步预检，无冲突且无需补充确认时打开一次发布确认。未知档期仍需明确勾选，已知冲突不能豁免 |
| 通知 | 普通任务事件 | 无需验收任务的通知只读即可；正式通告仍须本人知悉 |

FR-02／AC-02 的任务完成方式、FR-04 的场戏与分镜稿确认、FR-06／AC-06 的资源预约、FR-07 的发布入口及通告相关规则依此细化。原有容量、权限、版本、来源及正式回执约束继续适用；不扩大任何岗位能力，不增加后台自动检查。
