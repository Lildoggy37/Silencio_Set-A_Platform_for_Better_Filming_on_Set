# Silencio Set · 测试与验证方案

版本：D0.10  
状态：已确认测试层次、关键用例及证据规则；未编写完整自动化脚本，本文全部用例未执行，不是测试报告。

## 1. 范围与依据

依据[需求V0.8](../requirements/01_Silencio_Set需求分析.md)、[SUP补充需求](../requirements/README.md)及[需求追溯矩阵](08_需求追溯矩阵.md)，覆盖正常、边界、异常、权限、并发及恢复路径。基础业务不配置模型也须独立验证，随后验证Diane增强能力。

本章提供测试设计，不提前生成通过结论。测试框架及依赖在实施时锁定，真实邮箱、密钥及私人剧本不进入公开测试数据。

## 2. 测试层次与环境

| 层次 | 验证范围 |
|---|---|
| 单元 | 权限计算、状态转换、时间重叠、转场、时段资源峰值及用量汇总 |
| 数据库及接口集成 | 数据约束、事务、鉴权、版本冲突、幂等及真实并发 |
| 后台任务 | Outbox、重复消息、Worker中断、租约接手、重试及持久结果 |
| 页面端到端 | 注册补资料、筹备、排期发布、发送通告及知悉 |
| 专项 | 安全、故障降级、备份恢复、兼容性、易用性及性能 |
| Agent评测 | 查询依据、生成质量、工具授权、人工审批恢复、耗时及token |

集成测试使用隔离PostgreSQL、Redis、RabbitMQ及测试私有文件目录，不用内存替身证明真实事务与并发正确。测试数据包含不同剧组、兼任及普通成员、管理员、资源负责人等；避免使用生产数据。邮件正常投递可由测试适配器验证，实际服务配置另行验证，不向无关真实邮箱发送测试邮件。

模型模拟用于确定性调度及故障注入，真实Qwen调用用于真实耗时、用量和生成质量，两者分开报告。并发测试使用同步屏障协调竞争点、独立数据库事务或连接，记录实际交错情况，不把快速顺序请求当作并发。

## 3. 编号与用例模板

沿用矩阵中的`TG-F01—F12`、`TG-S01—S04`、`TG-B01—B08`、`TG-N01—N11`测试组。用例格式为`TC-{组类别与序号}-{三位序号}`，如`TC-F06-001`。测试组是组织入口，不代表每组已有完整用例；本章先定义13项关键用例，其余仍待细化。

每条完整用例记录：编号及标题、关联FR/SUP/BR/NFR和验收条款、设计位置、前置数据、角色权限、输入及操作步骤、预期响应、数据库／文件／消息结果、清理方式、执行环境和证据、执行状态。一个用例可关联多项需求，不能只验证HTTP 200。

执行状态取未执行、通过、失败或阻塞。依赖未配置、参数未冻结等实际阻碍需记录原因；没有运行证据不标通过。

## 5. 端到端路径

| 路径 | 步骤及断言重点 |
|---|---|
| 入组 | 邮箱验证注册→登录→补昵称→接受邀请→查看授权内容；未完成资料或邮箱不匹配不得加入 |
| 筹备 | 发布任务→负责人开始并提交→指定人员验收→通知；验证责任与状态一致 |
| 排期通告 | 确认剧本→审核场戏→落实档期与资源→发布计划→通告审核发送→成员知悉；核对各版本引用 |
| 智能增强 | 查询或生成草稿→操作提案→人工决定→实际结果和用量；拒绝不执行、恢复不重复 |

UI按视觉参考V1入口组织，总览、排期、资源、成员为一级导航；不新增独立通告导航。剧本、任务及通知次级入口、移动交互未补齐时先列缺口，不能仅凭生成参考图判定端到端可操作。

## 6. 专项验证与验收门槛

安全测试覆盖跨组、SQL注入、存储型及反射型脚本、命令与路径输入、提示注入、CSRF和密钥泄露。未经授权变更及重复业务变更必须为零，任何失败都需修复并回归，不以高成功率抵消。

按非功能设计FB-01—12执行故障注入，检查失败范围、实际状态、用户下一步与恢复去重。备份恢复至少真实隔离演练一次，记录恢复点及耗时，不将备份文件存在当成恢复成功。

性能验证依照需求7.4及非功能设计第16节，先探索后冻结环境、负载和阈值，再独立正式验证；参数未冻结不得通过验收。异步受理、最终完成及各类别业务分开统计，模拟与真实API结果分报。

易用性按5名代表性试用者中至少4人在5分钟内查看本人安排并确认通知，记录说明内容、卡点和结果。兼容性固定Chrome、Edge版本，390像素宽度验证查看安排、确认通知及更新本人任务，检查键盘可达，不以桌面参考图代替移动测试。

AI质量按至少10段、合计30场戏人工标注样本验证，场戏F1暂定不低于0.85，人物及道具精确率、召回率单列；分镜按来源一致性、拍摄约束及可编辑性审阅，不以单一艺术评分替代。至少20次请求核对计量完整性，包含失败、重试及未知量；预算控制与计量分别判定，不将最低样本数当作容量证明。
