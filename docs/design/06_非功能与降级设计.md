# Silencio Set · 非功能与降级设计

版本：D0.5  
状态：已确认降级、缓存队列、安全恢复、监测告警及性能验证方案；具体参数与实施验证继续细化，本文不声明已实现或已通过测试。

## 1. 目标与边界

本章集中定义Fallback（降级或替代路径），对应NFR-01、02、03、04、05、09、10、11。降级不是隐藏故障或无限重试，而是在明确失败范围后保留安全可用能力；《04_关键流程与异常处理》保留各业务的事务、恢复及幂等细节。

系统仍为本地单机模块化单体，不因引入降级而承诺高可用。依赖共用同一进程、Redis实例或数据库时，按实际故障范围判断能力，不宣称所有故障下普通业务均可使用。

### 1.1 三类处理

- 可替代：辅助功能失败时提供人工入口，例如AI生成失败后人工编写分镜。
- 可延迟：业务或任务已持久受理但后续处理暂不可用时，显示实际等待状态，恢复后幂等继续。
- 必须阻止：身份、权限、正式数据或业务约束无法可靠验证时停止相应操作，不用缓存、模型判断或默认放行替代。

## 2. 统一降级策略

以下为设计与后续故障测试要求，不是测试结果。重试次数、等待上限、回源容量及告警阈值需在运行配置与测试环境固定后补齐。

| 编号与触发条件 | 替代路径及用户提示 | 恢复条件与不可突破的边界 | 故障验证 |
|---|---|---|---|
| FB-01 Diane超时、限流或不可达 | 有限重试；提示智能服务暂不可用，提供任务、资源、排期等普通页面入口 | 模型恢复且请求仍有效后由受控入口重试；不得伪造生成结果，基础业务不依赖模型 | 模拟模型断连、限流和延迟；检查普通业务及失败提示 |
| FB-02 AI拆解或分镜生成失败 | 保留已持久保存的草稿，允许人工编写、修正 | 明确区分部分草稿与完整结果，人工审核前不能成为正式资料 | 中断生成，核对已保存内容与审核状态 |
| FB-03 剧本解析失败 | 提供重新上传、TXT或粘贴正文入口，说明格式限制 | 新输入重新校验；扫描PDF不能假称OCR成功，失败版本不替换工作版本 | 使用损坏、扫描、加密及超限样本核对提示 |
| FB-04 PDF导出失败 | 网页版通告继续可查看，提供受控重试 | 原通告及访问权限仍有效；导出绑定确定版本，不返回旧PDF冒充新版 | 模拟导出失败和旧文件存在，检查下载来源版本 |
| FB-05 验证邮件发送失败或延迟 | 有限重试，按间隔重新获取；提示已受理与实际发送状态 | 请求仍有效才发送；重发使旧验证码失效，不能跳过邮箱验证 | 模拟邮件失败、延迟及重发，核对旧码失效和限流 |
| FB-06 RabbitMQ或Worker不可用 | 已持久受理任务显示等待处理；业务已提交的通知保留待投递事项 | 服务恢复后幂等投递、执行；不显示完成，不临时改为耗时同步执行 | 停止Broker或Worker后恢复，核对补投、重复消息和业务不重复 |
| FB-07 普通缓存读取失败 | 会话仍可验证且数据库容量允许时限流回源；否则提示繁忙 | 回源并发受限，禁止无限回源；执行仍校验数据库；整个Redis不可用时适用FB-08 | 分别模拟单缓存读取失败及整个Redis故障，检查访问和回源限制 |
| FB-08 会话或验证码所依赖Redis不可用 | 提示认证服务暂不可用，暂停需要相关验证的操作 | Redis恢复且会话或验证码仍有效后重新验证；不能降级为免认证，不能信任前端登录状态 | 断开Redis后直接调用受保护接口，确认不发生未授权读取或修改 |
| FB-09 保存请求超时、结果不明 | 提示正在核实提交结果；查询已有结果或用原幂等键重试 | 以数据库提交记录为准，不换新键盲目再次创建、批准、扣库存；非幂等修改先核对对象和版本 | 在提交前、提交后分别中断响应，确认仅一次有效变更 |
| FB-10 勘景照片缺失或加载失败 | 局部占位及错误提示，保留仍可正常读取的场地文字 | 文件恢复或授权重新上传后显示；不替换为其他照片，不将失效文件发给模型 | 移走测试照片或令下载失败，检查文字与错误占位 |
| FB-11 PostgreSQL不可用 | 明确显示服务不可用，停止正式修改；无法鉴权或查询时不返回假数据 | 恢复数据库连接并重新校验后继续；不能依据旧缓存批准预约或发布排期 | 模拟连接失败，检查无假成功、无缓存审批及恢复后状态一致 |
| FB-12 业务已提交但模型回答失败 | 依据后端实际结果提供确定性反馈，并标明回答生成异常 | 从已持久结果恢复展示；不为补回答重新执行业务 | 在业务提交后令模型失败，核对结果可查且仅一次执行 |

若数据库持久化受理失败，不返回任务已可靠受理；若仅Broker发送失败但任务及Outbox已提交，可返回已受理并明确等待投递。长时间等待须有可展示的原因和受控处理入口，具体停止条件随后台配置确定，不无限静默等待。

本阶段不自动切换其他模型供应商。跨供应商切换涉及数据发送范围、费用、能力及输出差异，需另行确认，不作为默认fallback。任何重试均受次数、总时限和预算限制；权限拒绝、业务冲突及参数错误不通过重复模型调用解决。

## 3. 页面呈现与UI规范衔接

视觉与信息架构以[UI视觉参考V1](ui-reference-v1/README.md)为准：总览、排期、资源、成员四个一级导航，剧本、场戏及分镜从项目资料入口访问，发送通告为排期内流程。本章只补状态及恢复交互，不新增独立通告导航或旧侧栏，不照搬参考图中的示例状态为真实业务。

| 状态 | 呈现规则 |
|---|---|
| 局部失败 | 在照片、导出或Diane区域就地说明，不用整页遮罩阻断无关功能 |
| 操作受阻 | 说明阻断原因及下一步，不只将按钮置灰；后端仍独立拒绝非法操作 |
| 结果不明 | 显示正在核实提交结果，不先断言失败或引导重新创建 |
| 旧数据展示 | 仅在权限仍可验证且业务允许时保留，标明更新时间、非实时及版本；跨剧组切换、退出或权限失效时清理相关显示，不用于审批发布 |
| 等待后台处理 | 显示真实阶段和任务状态，无法准确计算时不编造百分比 |

沿用纯色、方角、细分隔线和必要文字提示；错误用文字及符号说明，不仅依赖颜色，不新增常驻告警卡片堆叠。

### 3.1 通告发送状态

分开呈现通告发布成功、通知等待投递和成员尚未知悉。发布成功以数据库为准；消息投递成功不等于成员收到或已读，已读不等于明确知悉。部分接收人失败时如实展示，不把整批伪装为全部成功；补投不重复发布通告或迁移历史确认到新版本。

## 4. 恢复与验证原则

每次恢复重新检查身份、权限、来源版本、有效期和实际结果，不因依赖恢复就自动批准旧提案。恢复不会撤销已提交业务，也不抹除失败记录；前端刷新不能触发新的写操作。

测试记录需包含故障注入点、依赖状态、请求标识、预期降级、实际数据库结果、界面提示及恢复后的去重情况；区分模拟故障、真实API和正式性能测试。关键验收包括未经授权业务变更为零、重复业务变更为零、失败及未知状态不伪装成功、恢复后来源版本仍一致。

## 5. Redis与缓存策略

### 5.1 按用途区分

| 用途 | 策略 |
|---|---|
| 会话、验证码与限流 | 认证基础设施，不按普通展示缓存处理；不可用不绕过相关校验 |
| 总览统计与资源目录 | 按需缓存，键包含剧组、查询条件及必要权限范围；写入提交后失效相关缓存 |
| 正式审批与发布 | 不以缓存作最终判断，事务内检查数据库 |
| 个人敏感数据 | 首期不做跨用户共享缓存，避免误共享权限及私人信息 |

仅为确有重复读取压力的查询增加缓存，不为每张表默认建立缓存。缓存失效只能在数据库提交后触发；失效失败需记录并受TTL约束，展示缓存不承诺与数据库强一致。

### 5.2 穿透、击穿与雪崩

- 穿透：先校验参数和权限，必要时短期缓存不存在结果，创建相应数据后清理。不得将某用户的无权限结果当作所有用户的不存在结果共享。
- 击穿：热点重建使用互斥，未取得资格者短暂等待或返回繁忙，不全部回源；锁带有效期和持有者标识，只能释放自己持有的锁。
- 雪崩：TTL加入随机偏移，限制回源并发和数据库连接使用；认证已无法验证时不能借回源继续业务。
- 旧值覆盖：重建读取携带来源版本，写回检查是否仍适用，禁止旧版本覆盖已知较新的缓存。单纯比较后再普通写入仍有竞争窗口，具体实现须使用版本化键或原子条件写入并验证竞争场景，不能据此宣称审批可免数据库检查。

TTL、重建等待上限、互斥有效期及回源并发配置化，初值随开发环境测试确定。验证无效ID高频访问、热点过期、批量过期、并发更新与重建、缓存读取故障和全Redis故障，核对回源有界、无越权及无缓存批准。

## 6. RabbitMQ与任务队列

### 6.1 队列隔离

| 队列 | 内容 | 目的 |
|---|---|---|
| `notifications` | 验证邮件、邀请邮件、业务通知分发 | 不被文档或模型长任务阻塞 |
| `documents` | 剧本解析、通告PDF导出 | 独立限制CPU、内存和处理并发 |
| `agent` | Diane执行与恢复 | 独立限制模型额度及预算 |

以上是队列和进程隔离，不是微服务。首期共用一个RabbitMQ实例，API、普通Worker及AI Worker按资源配置启动；普通Worker可按需分别消费通知和文档队列，具体进程数、并发及预取在配置中确定，不能仅凭队列名称宣称通知已获得资源隔离。

### 6.2 投递、执行与确认

正常顺序为数据库保存任务与Outbox、发送并取得投递确认、Worker执行、持久保存结果、确认消费消息。消息可能重复，消费者按任务及业务执行标识幂等；持久结果提交前不提前确认消息。发送确认不等于消费成功，消费成功也不等于整次Agent执行结束。

Worker崩溃后允许重新投递，但先查询是否已完成。长任务记录心跳或执行租约；接手者须确认旧执行已失效，以原子条件取得新执行权。结果写回必须匹配当前执行标识，旧执行不能覆盖新结果。租约用于协调执行，正式写操作仍检查稳定业务执行键，防止租约过期后两个执行者造成重复变更。

死信用于隔离及排查，不能自动无条件反复回送。Broker重投、任务调度重试与业务重试分别记录；Worker退出、处理时限或消息确认配置在依赖版本锁定后逐项验证，不假设配置名称天然保证失败重投。

验证发送成功但回写失败、结果提交后确认前崩溃、执行租约过期、旧Worker延迟回写、消息重复及乱序。检查仅一次有效业务变更、终态不被回退、积压恢复不突破并发限制。

## 7. 超时与取消

| 层次 | 控制内容 |
|---|---|
| API请求 | 查询、锁等待和外部短调用设超时，耗时业务异步受理；响应超时不代表数据库必然回滚 |
| 文件处理 | 限制大小、处理时间及资源消耗，超限停止并安全清理临时内容 |
| 模型调用 | 分别限制连接、响应等待及整次执行时长 |
| Agent执行 | 限制轮数、工具调用、token预算及并发，所有恢复步骤沿用同一执行预算 |
| 人工确认 | 单独计时，不持续占用Worker；恢复重检权限、版本及有效期 |

人工等待不消耗模型工作时限或Worker运行时限，但仍计入总历时并受提案有效性约束；具体等待有效期与工作时限口径在运行参数表固定。取消表示停止后续步骤，不自动撤销已提交业务。外部模型请求可能已产生费用，取消不能保证立即终止远端处理；超时或取消后的迟到结果不得改写已失效执行。

## 8. 重试边界

| 情形 | 处理 |
|---|---|
| 短暂网络错误、模型限流 | 有上限重试，使用退避及随机抖动，尊重服务端等待提示；每次计入预算 |
| 数据库死锁、短暂锁竞争 | 回滚整笔事务后受控重试，重新检查权限、版本及业务状态 |
| 权限不足、输入非法、业务冲突 | 不自动重试，返回明确原因 |
| 重复消息 | 检查已有执行及结果，不等于重新执行业务 |
| 外部请求结果不明 | 优先核实，不因超时认定对方未执行；无法核实时保留未知状态，不盲目重放非幂等外部动作 |
| 达到次数、总时限或token上限 | 停止并记录原因，提供适用的人工处理入口 |

同一调用链的重试由明确一层负责，避免模型SDK、业务代码和Celery多层重试乘积放大。模型瞬时故障由模型适配层的有限策略负责，Agent调度层不整体重放已完成工具；后台阶段重试先检查持久结果。数据库重试在事务协调入口进行，页面不因冲突自动反复提交。每次尝试、失败及已取得用量均记录；未知用量不填零。

## 9. 最小监测与后续参数

至少记录缓存命中、回源量及重建等待，队列积压与最老任务等待时间，执行尝试、超时、重试原因及失败任务，Agent分类耗时与token。用请求、任务和执行标识关联，日志脱敏；身份、验证码及私人原文不作监测标签。

待固定参数包括缓存TTL与抖动范围、回源并发、Worker并发及预取、心跳与租约、各层超时、重试次数及退避上限、人工等待有效期、模型分类预算。结合本地机器、任务样本及Qwen额度测定初值，并通过故障测试后冻结；不将尚未测定的值写成性能承诺。

性能环境及负载模型、认证安全参数、备份恢复实施及告警阈值继续细化。NFR-01、02及11的性能阈值或分类预算未冻结，不能据此判定正式验收通过。

## 10. 账号、会话与密钥安全

邮件发送短期敏感载荷采用D03第2.2.1节设计，真实加密密钥独立保管；Redis密文记录有TTL，不进入普通日志、消息正文或长期任务结果。配置及载荷缺失不得降级明文发送或绕过验证。内部和外部接口的错误及重试边界见D05第24节。

| 项目 | 设计要求 |
|---|---|
| 密码 | Argon2id散列，不存明文，具体参数通过本机测试确定 |
| 验证码 | 短期有效、单次使用、重发旧码失效；按邮箱与IP限流，限制连续失败 |
| 登录 | 失败提示统一，成功后轮换会话标识，退出使当前会话立即失效 |
| Cookie | `HttpOnly`，HTTPS启用`Secure`并设置适当`SameSite`；本地HTTP例外不得用于对外部署 |
| CSRF | 修改请求检查令牌及来源，不以`SameSite`替代全部防护 |
| 个人资料 | 未补全昵称仅允许本人资料补全、认证辅助及退出，不放行剧组业务 |
| 密钥 | 后端读取环境配置，真实`.env`不入库，不进入前端、导出或日志 |

验证码有效期、重发间隔、登录限制、会话空闲及绝对有效期集中配置，实施前确定数值并检查边界，不散落在业务代码。会话校验与权限判断分别执行，不能因持有有效会话长期沿用旧岗位权限。参考依据沿用《04_关键流程与异常处理》第9节。

## 11. 权限与注入防护

| 风险 | 设计措施与验证 |
|---|---|
| 跨剧组越权 | 查询和写入均校验对象所属剧组及当前权限；测试替换URL、请求体、文件和任务ID |
| 过度授权 | 岗位、例外授权、对象责任及状态共同决定操作；权限变化及时重检，保护最后一名管理员 |
| SQL注入 | 查询参数绑定，排序列及动态字段白名单，不拼接用户输入；测试非法过滤及排序内容 |
| 脚本注入 | 昵称、任务、剧本及模型回答按文本或受限格式展示；富文本清理危险内容，测试存储型及反射型脚本输入 |
| 恶意上传及路径穿越 | 校验实际格式、大小及解析资源，私有目录不直接公开，路径由服务端生成；测试伪装格式及路径输入 |
| 提示注入及工具滥用 | 剧本和工具结果仅作为资料，工具目录及参数后端约束；测试资料中要求越权、跳过审批或扩大工具能力的内容 |
| 重要操作绕过 | 人工确认具体提案，执行前重新校验权限、版本和冲突；模型不能生成有效批准记录 |

首期不开放Diane任意访问网址、执行系统命令或读取任意文件的能力。不因日志、审计或错误定位需要保存密钥、验证码及完整私人原文；访问日志和导出内容同样遵循最小披露。

## 12. 备份范围与保护

沿用NFR-04：每日备份，目标恢复点不超过24小时，目标恢复时间不超过4小时。这是待演练验证的目标，不是已达到的承诺。

| 对象 | 备份或恢复策略 |
|---|---|
| PostgreSQL | 业务、版本、审计、任务及恢复所需记录一并保护 |
| 私有文件目录 | 剧本、勘景照片、通告PDF与数据库引用配套备份 |
| 配置说明 | 保存模板、依赖版本、迁移版本及恢复步骤 |
| 真实密钥 | 不混入普通备份包，独立安全保管，恢复时重新注入 |
| Redis会话和验证码 | 不作正式业务恢复依据，恢复后重新登录及验证 |
| RabbitMQ消息 | 不作唯一恢复依据，由数据库任务和Outbox核对补投 |

备份包含私人剧本与成员资料，限制访问并加密保管，不进入公开仓库；至少一份放在不同物理介质，同盘副本不能应对整盘损坏。备份保留周期、独立副本位置及加密凭证保管方式在实施前确定。

## 13. 备份与恢复流程

### 13.1 小项目维护窗口备份

1. 进入维护状态，暂停业务写入、任务消费及文件清理，等待在途操作结束；无法安全排空时不得宣称取得一致备份。
2. 生成数据库及文件配套备份，记录备份时间、应用及迁移版本、文件清单和摘要。
3. 校验备份可读性、摘要及数据库文件配套关系，记录结果；生成失败保留上一份有效备份，不冒充成功。
4. 恢复业务并检查任务消费状态，将有效备份复制到独立介质。维护状态下明确提示，不能暗示服务持续可写。

该方式以短暂不可写换取首期备份一致性，不额外引入在线快照或分布式存储。备份清单与数据库引用须配套，不能仅将任意时间的数据库和文件打包视作一致恢复点。

### 13.2 恢复及外部副作用

1. 停止API写入、Worker及投递程序，保留故障现场，选定可用且配套的备份。
2. 在隔离环境恢复数据库及文件，核对应用、依赖、迁移版本和文件引用；未完成核对不开放写入。
3. 重新注入密钥，重建临时状态并使旧会话失效，避免继续使用故障前认证状态。
4. 核对任务、Outbox、业务执行结果及检查点，分类处理已完成、未完成和结果不明事项，再受控启用投递及Worker。
5. 通过关键业务检查后恢复访问，记录选定恢复点、实际耗时、数据损失范围及未解决事项。

恢复旧备份不等于可以盲目重放外部操作。备份时间点之后的邮件可能已发出、模型可能已计费，且相关本地记录可能不在备份内；先核实，无法确认时标记结果不明并人工处理，不能仅凭恢复后的幂等表无记录判定从未执行。旧待确认提案不自动批准，恢复重新检查权限、期限、来源版本和实际结果。

### 13.3 必须执行的隔离恢复演练

实际演练至少一次，记录备份时间、恢复开始结束时间和可恢复数据时间点，验证数据库与文件一致、缺失文件不显示成功、历史版本及审批审计可查询、旧会话失效、权限仍有效，以及补投不重复产生业务变更。实际耗时和数据恢复范围与24小时／4小时目标分别比较；未演练或未达标不能判定恢复验收通过。

## 14. 监测与日志

首期采用结构化日志、基础指标及授权任务状态查询，不引入复杂分布式追踪平台。第9节的最小监测按下表展开。

| 范围 | 记录内容 | 定位目的 |
|---|---|---|
| API | 请求量、耗时、状态码及错误类别 | 慢接口及异常 |
| PostgreSQL | 慢查询、连接池等待、锁等待及事务失败 | 查询或竞争瓶颈 |
| Redis | 命中、回源、重建等待及连接失败 | 缓存效果及故障范围 |
| 队列及Worker | 积压、最老任务等待时间、执行耗时、重试及失败 | 区分排队慢与执行慢 |
| Diane | 分类耗时、模型及工具调用、token、预算停止原因 | 效率、成本及可控性 |
| 文件及备份 | 磁盘余量、文件缺失、备份成功时间及校验结果 | 存储耗尽及备份失效 |

日志以`request_id`、`job_id`及`run_id`关联，按需记录受控用户及剧组标识，不将这些高基数标识作为指标标签。禁止记录密码、验证码、密钥及完整私人剧本。指标按接口模板、状态类别、任务类型等有限范围聚合，不以原始带ID路径形成无限标签。

故障排查的运行日志与正式业务审计职责不同，不能以日志存在代替业务提交或审计完整。具体采集工具、保留周期及访问配置在实施时确定，不因本章描述而声称已有监测平台。

## 15. 告警与恢复提示

| 级别 | 典型情况 | 处理方向 |
|---|---|---|
| 严重 | 数据库不可用、磁盘接近耗尽、备份持续失败 | 优先阻止进一步损害，提示维护并排查 |
| 警告 | 错误率持续升高、任务积压、模型限流、重试异常增多 | 检查依赖、负载和并发配置 |
| 提示 | 单个任务失败、一次导出异常 | 记录并提供对应入口，不升级为全站故障 |

采用持续时间判断、重复合并及恢复通知，避免短暂抖动产生大量告警；阈值、观察窗口及恢复判定在探索测试后确定。合并不删除底层事件记录，依赖恢复也不意味着未完成业务已自动成功。

本地阶段先输出运行日志和状态；程序停止后不能依靠自身继续告警。进程外监测及主动通知需另行配置，不宣称当前设计已具备无人值守故障通知。告警及展示仍遵循权限和脱敏规则。

## 16. 性能验证方案

### 16.1 分开验证普通业务与AI

| 测试线 | 范围 | 结果边界 |
|---|---|---|
| 普通业务 | 概览、任务、排期、资源及通告查询；创建任务、提交及知悉确认；并发预约批准、计划发布 | 不经过模型，分别报告读、写及竞争操作，不用一个系统QPS掩盖差异 |
| AI | 筹备查询、场戏拆解、文字分镜及操作提案 | 分开报告排队、模型、工具及人工等待，包含失败和重试用量 |

模拟模型用于调度及故障验证，真实Qwen API用于真实耗时和用量验证，二者分开报告。按NFR-11至少20次请求进行计量完整性检查，不将该最低样本数当作容量或稳定性证明。

### 16.2 测试步骤与口径

1. 固定机器配置、操作环境、依赖版本、数据规模、缓存状态、请求组合及模型配置，说明测试是否同机产生负载。
2. 使用合成数据构造不同规模，明确同一资源竞争、同一剧组写入及不同剧组访问，避免用无竞争随机ID结果替代热点竞争结果。
3. 从低并发逐步增加，记录吞吐、响应P50／P95、错误率、CPU、内存、连接及队列等待。分别标记缓存冷启动与预热结果。
4. 到达瓶颈后检查限流、排队及拒绝是否受控，不为了吞吐绕过锁、权限或冲突校验。
5. 根据探索结果确定配置及验收阈值，冻结后独立执行正式验证，不用同一轮调参结果直接判定通过。

HTTP异步受理耗时与后台完成耗时分别统计；`202`不能作为任务完成。业务冲突、限流、系统故障及任务最终失败分别计数，不能把预期拒绝静默剔除以提高成功率。具体请求组合、持续时间、负载和阈值沿用需求7.4的待确定流程。

同一资源并发审批受锁及正确性约束，不能与普通读取共用一个吞吐结论。单机测量只说明该环境及数据条件，不外推为线上高可用或未测规模的高QPS承诺。

### 16.3 验收输出

- 环境、配置、数据规模、缓存及模型条件说明。
- 测试脚本、请求组合、原始结果及可复现步骤。
- 分类吞吐、延迟、错误与资源占用统计，瓶颈及过载处理分析。
- 冻结参数、正式验收结论及未通过事项；区分未确定、未执行、未通过及已通过。
