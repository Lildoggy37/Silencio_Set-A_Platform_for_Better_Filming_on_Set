# Silencio Set · 寂静片场需求分析文档

版本：V0.8（讨论稿）  
项目类型：面向学生剧组的Web协作系统  
后期智能助手：Diane  
编制状态：已取得负责人归纳的外部反馈；原始材料待补充，产品试用与性能验证尚未开展。

## 1. 背景与目标

### 1.1 问题陈述

项目发起人最初观察到，学生剧组可能存在职责不清、任务通过聊天零散发布、成员档期难以汇总、设备和道具状态不透明等问题，容易出现重复沟通、任务遗漏和临场冲突。随后，发起人通过小红书发帖及与学生剧组交流，归纳出资源稀缺、人情化管理、分镜与通告准备不足、现场时间分配失衡、收音条件不足、勘景不充分及创作意见不一致等反馈。

这些反馈为资源约束、职责协调和筹备流程问题提供初步外部依据，也暴露出现场场记与素材归档等现有需求尚未覆盖的方向。当前材料是发起人的归纳，尚未附原始帖子和交流记录，不据此推断问题频率或软件效果；档期冲突、文件格式覆盖和Agent收益仍需进一步验证。逐项问题与需求影响见《03_人工核实说明》FB-01至FB-08。

项目名称为Silencio Set，中文为“寂静片场”。Silencio取自大卫·林奇电影《穆赫兰道》中的寂静俱乐部（Club Silencio），表达项目发起人对导演的致敬；Set指影视拍摄的片场，两者结合使名称具有明确的影视语境。

“寂静片场”还引申为减少管理混乱产生的噪声：职责不清可能带来导演的急躁指责，安排反复可能引发演员的抱怨，信息不透明也可能造成工作人员之间的猜测与议论。这些情形反映的是协调压力。项目希望通过清楚的分工、透明的资源状态和一致的拍摄安排，减少不必要的争执与反复询问，使剧组更专注于摄影和创作。这一命名含义用于解释个人项目的出发点。

### 1.2 项目目标

1. 明确任务负责人和操作权限，使成员知道自己需要完成什么。
2. 集中展示人员档期、拍摄计划和资源状态，提前发现冲突。
3. 提供剧本版本、场戏拆解、分镜资料和变更提醒等功能，支持完整的拍摄筹备流程。
4. 在基础管理功能完善后引入Diane，通过已有业务能力辅助查询、提出建议和执行经授权的操作。
5. 对重要业务变更实行负责人审核确认，保留依据与操作记录。

系统不能保证消除全部协作矛盾，也不代替导演、制片等人员承担创作和管理责任。

### 1.3 术语

| 术语 | 本文含义 |
|---|---|
| 剧组 | 围绕一个影视项目建立的成员、资料和业务数据协作空间；首期一个剧组对应一个项目，同一用户可以加入多个剧组 |
| 场景／场戏 | 剧本中具有相对明确地点、时间和连续行动的一段内容 |
| 分镜稿 | 镜号、景别、画面、运镜、声音等字段组成的可编辑文字表格，首期不要求生成图片 |
| 拍摄计划 | 对场戏的日期、时间、地点、人员和资源作出的安排 |
| 场景筹备 | 为某场戏整理人员、场地、道具和设备等准备事项 |
| Diane | 基于授权项目资料，进行查询、分析、建议和受控业务操作的Agent助手 |

## 2. 目标用户与使用场景

### 2.1 用户角色

首期面向学生短片、课程作品和校内影视社团剧组。用户可以兼任多个业务身份；身份提供默认权限，实际操作仍以所在剧组授予的权限为准。

| 角色 | 主要使用需求 | 默认权限范围 |
|---|---|---|
| 剧组管理员 | 邀请成员、维护组织与权限 | 管理剧组成员及配置；业务发布权限需明确授予 |
| 导演 | 审核剧本拆解、分镜及拍摄建议 | 编辑和确认创作资料，查看相关计划 |
| 制片／排期负责人 | 汇总档期、协调资源、发布拍摄安排 | 管理任务、排期和资源预约 |
| 编剧 | 上传和修订剧本 | 编辑剧本，查看关联反馈 |
| 摄影、美术等工作人员 | 接收任务、登记与反馈资源情况 | 更新被授权的任务和资源 |
| 演员 | 填报可用时间、确认拍摄通知 | 维护本人档期，查看本人相关安排 |

所有成员均可查询本人有权访问的信息。身份名称本身不允许绕过权限检查。

### 2.2 典型场景

**场景S-01：组建剧组并分工。** 创建者建立剧组，邀请成员，为成员设置一个或多个身份。制片发布筹备任务，指定一名负责人、协作人和截止时间，成员更新进度。

**场景S-02：整理剧本与筹备事项。** 编剧上传DOCX、PDF或TXT剧本，选择当前工作版本。导演与相关成员建立场戏记录、关联原文并整理人物和资源需求，分配场地联系、道具准备等任务，通过页面查看筹备进度。

**场景S-03：制定与调整拍摄安排。** 制片查看成员档期和资源预约，在页面编排拍摄计划，系统检查冲突。场地临时不可用时，制片查看关联场戏和受影响成员，修改草案并重新发布，成员确认新安排。

**场景S-04：管理资源借还。** 摄影成员申请某时段的设备，资源负责人检查余量后确认预约，拍摄当天登记借出和归还。制片查看尚未归还或已停用资源，及时处理后续安排。

**场景S-05：检查任务与开拍准备。** 导演通过场戏详情查看负责人、任务完成情况、参与成员、场地和资源，识别未完成事项。成员更新任务并提交结果，确认人审核完成。

**场景S-06：使用后期智能辅助。** 基础功能完善后，导演可向Diane询问“周六第三场戏还缺什么”。Diane基于已有记录进行查询和整理，标明未知项；也可辅助生成拆解、文字分镜及调整建议。正式业务变更仍需授权负责人确认。上述工作均保留普通页面操作入口。

## 4. 系统边界与约束

### 4.1 业务范围

基础阶段覆盖创建剧组、成员与权限、任务、剧本版本、人工场戏拆解、文字分镜资料维护、档期、资源、拍摄计划及通知确认。这些功能能够通过普通页面独立完成。通过桌面浏览器完成主要管理操作；移动浏览器优先满足查看安排、确认通知和更新任务。

增强阶段在基础功能完成并通过验收后接入Diane，复用已有业务接口提供自然语言查询、筹备检查、辅助拆解、文字分镜生成和操作提案。接口仍执行原有权限、版本及冲突规则，Agent不形成另一套独立业务规则。

不包含视频拍摄与剪辑、自动生成成片、演员招聘、财务结算、合同管理和作品发行。本轮不讨论图像设计、多模态生成及展示需求。自动优化排期、外部日历同步列入后续讨论范围。

系统协调已有资源，不能增加经费或设备，不能代替现实领导、现场勘察、专业收音及创作协商。反馈涉及的通告标准化、现场场记与素材索引、镜头耗时管理、勘景清单和创作决策记录暂列候选，尚未新增为已确认功能。

### 4.2 前提与限制

- 成员需要主动登记档期、任务和资源状态；系统只能根据已记录的信息判断。
- 剧本支持DOCX、PDF、UTF-8 TXT和正文粘贴。单个上传文件不超过20MB，提取正文不超过10万字，上传后展示提取结果，由用户检查确认；当前PDF支持含文本层的文件，扫描件、加密文件或无法提取正文的文档提示原因并允许用户改用其他格式或粘贴正文。扫描件OCR不纳入本轮范围。
- 剧本保存范围与AI单次处理范围分别限定，允许保存完整剧本，增强阶段按场戏选择分析内容；单次分析范围依据模型能力和实测预算确定。
- 首期资源分为可复用资源（设备、道具、场地）和数量型耗材；耗材只登记数量及需求，不实行时间预约。
- 业务资料以中文为主；电影创作建议应由人员审阅，不能当作确定事实。
- 基础业务阶段无需配置模型即可使用。增强阶段计划采用LangChain及Qwen API；模型额度、部署资源和运行预算需评估后确定，具体技术安排留到后续设计。
- 已取得发起人归纳的小红书及学生剧组交流反馈，原始材料、人数和交流日期尚未提供；未开展产品试用、压测和AI质量测试，下文相关数值是拟定验收目标。

## 5. 功能需求

优先级定义：高为项目核心能力；中为核心流程后的完善能力；低为后续扩展。优先级表示业务重要程度，开发阶段表示先后顺序：即使Diane相关需求为高优先级，也在基础业务完成后接入。FR代表功能需求，AC代表对应验收条目。

### FR-01 剧组创建、成员与权限（高）

**使用者与条件：** 已登录用户创建剧组；管理员管理成员，其他成员按权限使用。

**输入与流程：** 输入剧组名称和简介，创建后邀请成员；邀请有效期为7天，可撤销，接受后失效。管理员可给成员分配多个身份及权限，系统展示权限范围。任务负责人或计划涉及成员被移除前，要求处理其未完成责任和安排。

**输出与异常：** 输出成员及权限列表。无效邀请、越权操作返回明确提示；不允许移除最后一名管理员。

**AC-01：** 创建剧组后创建者成为管理员；受邀用户加入后只能访问授权剧组；普通成员调用管理操作被拒绝且数据不变；一人可以兼任导演和编剧。移除成员或修改权限前须展示变更及未完成责任；最后一名管理员不能被移除或取消管理权限，未处理的责任阻止移除。

### FR-02 任务分配与进度跟踪（高）

**使用者与条件：** 有任务管理权限者分配任务，负责人或获授权成员更新任务。

**输入与流程：** 输入标题、说明、唯一负责人、可选协作人、截止时间及关联场戏；任务状态为待处理、进行中、待确认、已完成或已取消。负责人提交完成结果，由任务发布者或指定确认人验收；退回时填写原因，任务回到进行中。管理员获授相应权限后可以兼任确认人。

**输出与异常：** 输出任务列表和状态历史。缺少负责人不能发布；任务到期未完成时标记逾期，不自动认定完成。取消需记录原因，保留历史。

**AC-02：** 已知一个未完成任务，负责人提交结果后进入待确认；确认者通过后进入已完成，退回时必须填写原因且任务回到进行中。无权限者不能修改任务；逾期任务可被筛选。

### FR-03 剧本与版本管理（高）

**使用者与条件：** 编剧或具备剧本编辑权限者上传内容。

**输入与流程：** 上传DOCX、PDF或TXT，或粘贴正文，填写版本说明；系统提取正文并供用户检查段落及阅读顺序。每次提交形成独立版本，选择一个当前工作版本；拆解和分镜均标记来源版本。

**输出与异常：** 输出提取正文和版本记录。不支持的格式、损坏或加密文件、无可提取文本及超限内容给出明确提示；文件解析失败不创建有效版本，保留其他版本。新版本不覆盖旧版已确认资料，关联结果提示需要复核。

**AC-03：** 使用内容相同的DOCX、文本型PDF和TXT样本分别上传，按6.3的正文提取口径核对内容与顺序，用户可检查并确认正文；上传两个版本后均可查看。切换当前版本后旧版拆解仍标记原版本；扫描或加密PDF显示处理限制，非法输入不创建有效版本。

### FR-04 剧本拆解与人工审核（高）

**使用者与条件：** 授权成员选择一个剧本版本建立拆解，导演或获授权者确认结果。

**输入与流程：** 基础阶段由成员通过页面录入场戏编号、地点、日夜、角色、道具和制作需求，关联原文片段，修改后提交审核。增强阶段可由Diane生成待审草稿，用户修改、补充、否决并确认；无法确定的信息标记待确认。

**输出与异常：** 输出待审拆解表和确认版本。必填项缺失时不能提交；后期智能分析失败仍可人工编辑，保留剧本并允许重试；AI建议与原文明确信息分开展示。

**AC-04：** 未配置Diane时可以完成场戏录入、修改、审核及关联原文；确认前不得作为已确认事实发布。后期生成的拆解首先为待审核，直接提取的场戏记录可查看原文依据，修改历史可以追溯。

### FR-05 人员档期登记（高）

**使用者与条件：** 成员维护本人档期，排期负责人查看剧组内排期所需信息。

**输入与流程：** 成员登记日期、起止时间及可用／不可用状态。未登记时间显示未知；默认不公开个人不可用的私人原因。

**输出与异常：** 输出档期视图。起止时间无效时拒绝保存；同一成员相互矛盾的区间要求修改或明确覆盖，不静默合并。

**AC-05：** 已登记不可用的时间与拍摄安排重叠时出现冲突；未登记时间显示待确认，不显示为可用；包括管理员在内的成员不能通过页面、接口或Diane修改他人档期。

### FR-06 资源登记、预约与借还（高）

**使用者与条件：** 授权资源负责人登记资源，授权成员提出使用需求。

**输入与流程：** 登记资源名称、类型、数量、负责人和状态。可复用资源按时段预约，由资源负责人确认后生效；待审批申请不保证资源可用，确认时重新检查冲突。设备和道具记录借出、归还，场地不涉及借还。耗材记录需求及剩余数量。

**输出与异常：** 输出资源清单、预约和借还状态。可复用资源停用或数量不足时禁止确认新增预约；归还超期保留未归还标识；耗材不足时提示缺口。

**AC-06：** 同一设备在重叠时段已被确认预约时，不允许再次确认超量预约；两个待审批申请即使提交时无冲突，也必须在确认时重新校验。资源负责人在查看资源、数量、时段及余量后批准，其他成员不能代为批准。拒绝或待审批预约不计为正式占用；设备归还后更新借还记录。

### FR-07 拍摄计划与冲突检查（高）

**使用者与条件：** 有排期权限者基于已确认场戏及已登记信息编制草案，由具备发布权限者发布。

**输入与流程：** 指定日期、起止时间、场地、参与成员和资源；排期负责人为各场次填写结束后的转场准备时间，单位为分钟，默认0。系统按BR-05检查人员重叠及转场间隔、已知不可用时间、资源超量占用和场地冲突。用户可调整草案；未知档期列出成员及对应时段。

**输出与异常：** 输出草案、冲突列表和发布版本。存在已知时间、转场间隔或资源冲突时阻止发布。存在未知档期时，发布负责人须主动勾选“已知晓上述成员档期尚未确认，仍发布本次安排”，系统记录其身份、时间、计划版本及未知档期清单后才允许发布，保留待确认标记并通知本人。该动作不改变成员档期，也不能豁免已知冲突。修改已发布计划形成新版本。

**AC-07：** 同一成员的拍摄时间重叠时阻止发布；上一场12:00结束且转场准备30分钟时，该成员下一场12:29开始不能通过，12:30可以通过该项检查。存在未知档期且未勾选确认项时不能发布，勾选后保存确认记录并通知本人；计划或相关档期变化后重新检查并确认，不沿用旧版本确认。已知不可用时间不能通过勾选豁免。首期不承诺自动求得最优排期。

### FR-08 通知与确认（高）

**使用者与条件：** 拍摄计划发布、任务分配或已发布计划变更触发站内通知。

**输入与流程：** 系统向受影响成员提供通知、相关版本和变化摘要；成员点击“确认知悉”，负责人查看确认情况。

**输出与异常：** 输出未读、已读、已确认状态。已读不等于已确认；通知失败可以重试，通知失败不回滚已发布计划；页面持续显示待确认事项。

**AC-08：** 发布计划后参与成员收到对应版本通知；修改后旧确认不算新版本确认；重复投递不产生重复业务通知。

### FR-09 Diane查询与筹备检查（高）

**使用者与条件：** 增强阶段，基础业务已完成验收，剧组成员在本人权限范围内发起对话。

**输入与流程：** 接收自然语言问题，查询任务、场戏、档期和资源，回答项目状态，列出准备缺项和关联记录。涉及“明天”等表达时显示解析后的具体日期，默认时区为Asia/Shanghai。问题有歧义时先澄清。

**输出与异常：** 输出有依据的回答、记录链接及未知项。无资料时明确无法判断；模型不可用时提示失败并提供普通页面查询入口；剧本文本中的指令不能成为权限或操作授权。

**AC-09：** 对“第三场戏还缺什么”回答可追溯至相关记录；未登记设备状态时不宣称设备已就绪；询问其他剧组资料不能获得其内容。

### FR-10 Diane操作提案与人工确认（高）

**使用者与条件：** 增强阶段，基础业务已完成验收，授权成员要求Diane通过现有业务接口批量创建任务、调整计划或提出资源预约。

**输入与流程：** Diane生成提案，展示目标对象、修改前后内容、受影响成员和已知冲突。具备7.3所列对应业务权限者点击确认后执行；查询及生成未发布建议不要求额外确认。申请资源预约仅创建待审批申请，不能代替资源负责人批准；计划提案也不能绕过未知档期确认及冲突检查。

**输出与异常：** 输出执行结果和记录。拒绝或取消后数据不变；确认前目标数据已变更时提案失效，要求重新检查；执行前重新验证权限。删除资料、移除成员和修改权限首期只通过普通管理页面执行。

**AC-10：** 批量创建任务必须先展示提案；无权限确认不能执行，拒绝后数据不变；同一提案重复确认不产生重复任务。生成提案后目标记录、相关资源状态或权限变化，旧提案不得直接执行，须重新检查并展示更新后的提案供确认；一组提案中的必需操作无法全部完成时，不展示整体成功，并返回实际处理结果。

### FR-11 文字分镜与拍摄建议（中）

**使用者与条件：** 导演选择剧本版本和场戏，填写分镜内容；增强阶段可输入创作要求及已知条件，请Diane辅助生成。

**输入与流程：** 基础阶段通过页面维护镜号、景别、画面内容、运镜、对白／声音和建议时长，支持编辑、保存及确认。增强阶段Diane可生成上述文字草稿及拍摄建议，考虑已登记设备和场地限制，新增资源需求明确标记为建议。

**输出与异常：** 输出带来源版本的文字分镜草稿和建议。不确定时长标为估计；模型失败不覆盖已有分镜；剧本更新后提示复核。

**AC-11：** 未配置Diane时分镜仍可逐项编辑、保存和重新打开；未确认草稿有明确标识。后期AI生成结果可人工修改，不自动转成正式拍摄计划或资源预约。不以“艺术效果优秀”作为确定性验收条件。

### FR-12 变更影响提示（中）

**使用者与条件：** 成员变更剧本工作版本、本人档期、资源状态或剧组成员关系，系统检查已录入的关联记录。

**输入与流程：** 根据记录标识和版本列出受影响场戏、分镜、任务和计划，提醒负责人复核，不自动改写已发布安排。场戏资源需求未关联具体资源时标记“资源未落实”；场戏或分镜来源版本不同于当前剧本版本且未完成复核时标记“来源版本待复核”；关联资源停用或关联成员退出、被移除时标记“关联对象不可用”。成员修改档期后与已发布安排冲突或变为未知时，标记“档期变更待复核”。

**输出与异常：** 输出问题类型、触发记录及受影响对象清单。影响范围仅涵盖系统已录入并建立关联的信息；未录入的需求或未建立关联的外部安排无法判断。提醒只有在重新检查确认问题已处理后解除，不能仅靠已读通知消除。

**AC-12：** 已被计划使用的设备停用后，对应安排出现“关联对象不可用”；资源需求未绑定资源时显示“资源未落实”，不得计为已准备完成；切换剧本工作版本后，旧版关联资料显示“来源版本待复核”。关联成员不可用或档期变化时提示对应安排。恢复资源、补全关联或完成复核后重新检查并解除对应提醒，原版本及历史记录保留；不对未录入事项宣称已完成影响检查。

## 6. 输入与输出数据定义

本章定义业务数据及校验口径，作为各功能输入、输出与验收的共同依据；不规定数据库表结构、字段存储方式或接口协议。长度限制为本轮提出的校验基线，后续调整时应同步修改对应验收条件。

### 6.1 通用约定

- **标识与关联：** 每条业务记录具有系统生成的唯一标识；关联字段引用记录标识，名称用于显示。同一业务对象的关联记录须属于同一剧组，成员引用须指向该剧组成员。
- **必填与草稿：** “是”表示提交有效记录时必填；“条件必填”按表中条件检查。编辑草稿可暂缺内容，但发布、提交审核或执行前须通过校验。系统生成的必填字段不要求用户录入。
- **文本与数量：** 短文本长度在去除首尾空白后计算，纯空白不满足必填要求；正文上限按字符数计算，包含标点、空格和换行。数量取正整数，库存可为0；状态只能取列出的值。
- **时间：** 日期为YYYY-MM-DD，日期时间显示为YYYY-MM-DD HH:mm，默认时区Asia/Shanghai，精度为分钟；区间结束晚于开始，时长以分钟或秒明确标注。起止区间可以跨日。
- **空值：** 非必填信息缺失时显示“未填写”或“未知”，不自动替换为0、可用或已完成；空列表表示未添加条目，不证明无需该项资源。
- **校验反馈：** 输入错误应指明字段、原因及允许范围，保留可修正的输入；输出列表无记录时显示空状态。以上约定不允许绕过权限和安全检查。

| 用户确认 | 展示提取正文及异常警告，用户可修正后确认；修正与确认结果归入对应版本 | 未确认内容不进入有效版本；已确认正文能够用于人工拆解和原文引用；用户修改正文后更新相应引用依据 |

### 7.4 性能与调用用量验收约定

本节先确定测试方法和指标补定节点，不预设未经确认的压测数值。探索性测试用于确定可接受的验收基线；正式验收前由项目负责人确认并冻结条件与阈值，不能在看到正式结果后调整阈值以判定通过。

| 验收对象 | 测试前置条件 | 需补定的指标 | 补定节点 |
|---|---|---|---|
| 普通业务 NFR-01 | 固定代码版本、服务器配置、数据库数据规模、网络条件及缓存状态；固定查询、写入和排期检查的请求比例，测试账户具有相应权限 | 并发数或请求到达速率、预热和正式测量时长、各类请求P95上限、错误率上限及过载判定条件 | 基础业务可独立运行后开展探索性压测；基础业务正式性能验收开始前确认并冻结 |
| AI时效 NFR-02 | 接入实际Qwen模型，固定模型标识、生成配置、可用额度、输入样本和大小；分别准备查询、场戏分析、操作提案，固定重试及并行配置 | 请求受理、排队和各类任务完成耗时目标，完成率下限、并行数、队列上限及超时设置 | 模型接入并完成分类样例测试后，智能增强正式验收开始前确认并冻结 |
| Agent用量 NFR-11 | 调用记录可采集；每个请求可关联所有模型与工具调用及重试；明确模型用量字段及采用的计费口径 | 各任务类别token预算、最大轮数、超时限制及成本预算；用量不可获取时的记录与处置方式 | 先以不少于20次请求验证计量记录，再根据分类结果补足样本、制定预算；智能增强正式验收开始前冻结 |

统一测量口径如下：

- **普通请求耗时与吞吐量：** 耗时从测试客户端发起请求至收到完整响应，包含网络传输；正式窗口排除预热期。成功响应按请求类别统计P50、P95，不用总体均值替代；同时列出失败及超时数量。吞吐量为窗口内完成请求数除以窗口秒数，同时报告成功吞吐量。异步任务的受理响应和实际完成时间分开统计。
- **错误率与过载：** 正常负载场景的分母为合法且已授权的请求数，分子包括服务端错误、超时、连接失败及非预期拒绝；测试工具未能发出的请求单列并说明。故意构造的非法输入、越权和冲突请求另作功能测试，不混入正常错误率。过载场景单列拒绝率、排队情况和恢复结果，限流响应不能当作成功业务完成。
- **Agent耗时：** 受理耗时为服务收到请求至返回请求标识及初始状态；排队耗时为已受理至开始执行。总耗时为收到请求至完成或失败；出现确认等待时分别记录提案生成、人工等待及确认后执行耗时，并报告扣除人工等待的处理耗时。统计覆盖工具执行和重试，多项并行操作不通过简单相加计算总耗时。
- **token与成本：** 按单次业务请求汇总所有模型调用及重试的输入、输出token；能够取得的缓存或其他计费用量分类保留，避免重复计数。用量缺失不得填0，实测与估算分开报告；成本按所选模型实际计费类别计算，注明单价依据。查询、拆解和提案分别统计，不能用统一均值直接确定所有任务预算。
- **样本与判定：** 报告测试环境、样本数量、输入规模、原始记录和统计结果；NFR-11的20次请求是计量完整性检查的最低样本数，不代表每类任务已有足够样本证明容量或稳定性。达到冻结的阈值且故障、过载与超限处理符合要求方可通过；未补定、未测试、未通过和已通过分别记录。

当前NFR-01、NFR-02的数值阈值及NFR-11的分类预算均处于待补定状态。暂不影响需求文档作为讨论稿审阅，但正式系统验收前须完成上述节点；确定后更新需求版本并记录依据，环境或模型发生显著变化时重新评估。

## 8. 优先级与分阶段验收

### 8.1 开发阶段与优先级

保留FR-01至FR-10的高优先级、FR-11和FR-12的中优先级。优先级不代表必须在同一阶段完成。

| 阶段 | 需求范围 | 完成条件 |
|---|---|---|
| 基础业务阶段 | FR-01至FR-08的普通页面能力，以及FR-11的人工文字分镜维护、FR-12的变更提示 | 无模型配置时可独立完成剧组管理、筹备和计划发布；通过基础业务验收后再接入Agent |
| 智能增强阶段 | FR-09、FR-10，FR-04的辅助拆解和FR-11的辅助生成 | 通过已完成的业务接口提供能力，沿用相同权限与校验；补充智能功能、安全及用量验收 |
| 后续扩展 | 自动优化排期、外部日历同步 | 不计入当前验收；图像及多模态需求另行讨论 |

### 8.2 基础业务验收

使用人工构造的一个学生短片剧组，配置导演、制片、编剧、演员和工作人员，录入不少于3场戏、5项任务及5项资源：

1. 成员加入并获得正确权限，一人可以兼任身份。
2. 分别上传DOCX、文本型PDF和TXT剧本，人工建立并审核场戏拆解，维护文字分镜和来源版本。
3. 登记档期和资源，创建拍摄草案，构造并排除一次人员冲突和一次资源冲突。
4. 发布计划，成员确认通知；调整计划后重新确认新版本。
5. 在页面查看某场戏的任务、资源和参与人员，识别未完成及未知事项。
6. 完成一次设备预约、借出和归还；停用已被安排使用的设备，验证受影响计划得到提示。
7. 在没有模型配置的条件下完成全部基础业务，执行权限及注入防护检查；按7.4冻结测试条件与阈值后开展普通业务正式性能验收。

### 8.3 智能增强验收

1. 在基础验收通过后启用Diane，完成基于既有数据的查询和筹备检查，回答能指向业务记录并指出未知项。
2. 生成场戏拆解和文字分镜草稿，人工修改和确认，验证原有页面仍能独立维护相同资料。
3. 确认一次合法业务提案，拒绝另一次；验证重复确认、过期提案和越权操作不会产生错误业务变更。
4. 模拟模型失败及提示注入，普通管理功能仍可使用，权限和确认流程不被绕过。
5. 对不少于20次Agent请求检查耗时和token记录完整性，覆盖重试和失败；按7.4补足分类样本、冻结时效目标与调用预算，再验证正式时效及超限控制，分别报告结果。

各阶段按对应FR的AC条目及NFR验收；基础阶段不以Diane可用为前提。具体压测数据和性能阈值暂不确定；AI质量及恢复数值保留为拟定目标，需要实际测试和恢复演练。Agent预算在模型接入并建立分类用量基线后确定。业务规则已确认不代表系统已经实现或通过验收。
