# 资源登记与时段预约

当前已接入设备、道具、场地的登记与维护、管理员指定审批负责人、预约申请／批准／拒绝／取消、时段余量查询，以及离组前的资源责任检查。迁移头为`0009_resources`。本轮没有操作Docker、连接真实数据库或调用Qwen。

借还、耗材库存、场地详情及图片、正式预约变更申请、拍摄计划依赖和资源通知消费仍待实现。预约到期不表示实物已经归还；响应以`physical_inventory_status`或`dependency_check_status=not_implemented`标明相应边界，不返回虚构的检查成功。任务通知消费者不会消费资源事件。

## 核心代码与流程

| 文件 | 作用 |
|---|---|
| `resources/domain.py` | 半开时段的同时占用峰值、容量与版本检查 |
| `resources/models.py` | 资源、范围授权、预约、幂等回执和变动事件 |
| `resources/repository.py` | 当前权限、同组引用、串行审批、事务审计和离组阻断 |
| `api/resources.py` | 资源与预约HTTP接口、限流和CSRF |
| `frontend/src/resources/ResourceBoard.tsx` | 登记、授权、查询、预约与审批页面及明确核对 |

申请先保存为`pending`，不保证余量。批准后为`confirmed`，拒绝为`rejected`，取消为`cancelled`。拒绝必须说明原因；取消另存实际取消人、时间和原因，保留已有审批人、时间及说明。

容量按`[starts_at, ends_at)`计算。将已批准预约的起止数量变化按时间聚合，求申请时段内的同时占用峰值，再加本次数量。两个互不同时发生的预约不能简单相加；前一条结束与后一条开始相同也不算重叠。批准、资源减量与停用在事务内重新检查。停用不能影响未结束的已批准预约，减量不能低于其峰值。

写入共用：当前账号共享锁 → 剧组协调锁 → 锁后权限检查 → 资源行锁 → 预约行锁。岗位修改、成员退出和审批使用同一剧组协调器；资源变更、成功审计、回执、事件同事务提交。失败不返回成功，失败审计由独立事务记录。余量查询也短暂取得剧组协调锁，保证数量／版本与预约结果一致；这是首期偏正确性的取舍，尚无高QPS或锁竞争实测。

## 权限与隐私

- 具备`resource.manage`的制片可登记资源并维护本组资料；其他维护者还需对应资源范围。本轮暂不提供通用维护范围编辑器。
- 登记时可以先指定在组联系人，返回`review_ready=false`。此时没有审批权，待管理员明确授权；避免通过登记资料悄悄授予业务权限。
- 管理员通过专用授权接口检查`member.authorize`、资源版本和目标成员版本。目标已具备审批能力时可直接指定本资源范围；否则须明确提交`grant_review_permission=true`。
- 该显式选项将目标成员的`reservation.review`例外设为允许，包括替换既有拒绝，并递增成员版本、独立记录权限变化审计。它是有限业务授权入口，不是任意权限编辑器。
- 批准／拒绝都要求有效审批能力、当前资源负责人关系以及本资源审批范围。制片或管理员身份本身不带审批权，单独的范围记录也不覆盖明确拒绝。
- 转交删除旧的本资源审批范围，保留旧成员在其他资源可能需要的能力。范围及申请保存精确的入组时间，退出再加入不恢复旧授权或旧私人申请可见性。
- 资源目录对有`resource.read`的成员开放。预约详情只对申请人本次入组或当前有权审批者开放；管理员、资料维护者不能因此查看所有私人申请。余量接口只返回聚合占用，不返回他人申请人和审批说明。

## 实际HTTP契约

前缀`/api/v1/crews/{crew_id}`。分页大小1—20，页码1—100000；前端每页20。JSON请求体不超过16 KiB，修改校验Origin与CSRF，每IP／用户每限流窗口读120次、写10次。所有业务响应禁止缓存。

| 方法与路径 | 主要输入／结果 |
|---|---|
| GET／POST `/resources` | 分页目录／登记；登记返回201资源详情 |
| GET／PATCH `/resources/{id}` | 详情／维护；维护带`expected_lock_version`，不能直接改类型或负责人 |
| PUT `/resources/{id}/authorization` | `manager_member_id`、资源及目标成员版本、明确授予审批能力选项；200资源详情 |
| GET `/resources/{id}/availability` | 必填`range_start/range_end`；总量、版本、同时占用峰值、最少余量及已批准条数 |
| GET／POST `/resource-reservations` | 按当前可见范围分页，可筛资源和状态／提交申请；申请返回201预约详情 |
| GET `/resource-reservations/{id}` | 当前仍有权查看的预约详情 |
| POST `/resource-reservations/{id}/decisions` | `decision=accept/reject`、`decision_note`、预约版本；200预约详情 |
| POST `/resource-reservations/{id}/cancel` | `reason`及预约版本；200预约详情 |
| GET `/members/{id}/resource-responsibilities` | 本人或有移除权者预览；可见清单、总阻断数及受限条数 |

登记字段为`name`1—100字、`resource_type=equipment/prop/location`、`unit`1—10字、`total_quantity`1—1000000严格整数、同组在组`manager_member_id`及可空`description`最多2000字。耗材输入拒绝，不能暂用可复用资源假装支持耗材。

申请字段为`resource_id/starts_at/ends_at/quantity`，开始不早于提交时的数据库时间，时段大于0且不超过31天，数量不超过登记总量。`scene_id`暂仅接受null，非空拒绝，待场戏模块接入后补同组校验。时间使用带时区ISO整秒，存储UTC、界面统一北京时间。入组快照保留微秒，版本为1—2147483647严格整数。

资源详情包含负责人昵称、成员版本、`review_ready`与`allowed_actions`。预约详情包含ID、资源／申请人成员ID、时段、数量、状态、原审批及独立取消信息、版本、时间和`allowed_actions`；没有私人邮箱和账号ID。按钮提示不能替代服务端检查。

## 幂等与未知结果

登记、授权、申请、决定、取消必须带UUID格式`Idempotency-Key`。按剧组／用户／键摘要唯一保存，正文以动作、目标及规范JSON摘要绑定，回执另存本次入组时间。相同键不同内容409；离组再加入不能重放旧回执。重放前重新检查当前权限和对象可见性，返回原成功快照但清空操作提示；查询接口才代表当前状态。

页面先核对再确认，双击只发一次。网络中断、5xx或响应无法校验时，带键请求冻结原内容，用户只能明确用原键重试，不自动重放。只要页面会话保留，重试沿用原键；关闭浏览器会丢失内存草稿和操作键，重新操作前应先查询现状，尚无跨浏览器恢复清单。

资源维护PATCH不带键，版本冲突或结果未知先重新读取，保留输入，再核对新基线；不直接重发旧请求。普通冲突同样保留草稿，不把失败改成空结果。已确认写入不因后续刷新失败诱导重复提交。

主要错误：`FORBIDDEN/NOT_FOUND`、`VERSION_CONFLICT`、`RESOURCE_UNAVAILABLE`、`RESOURCE_IN_USE`、`RESOURCE_CAPACITY_CONFLICT`、`INVALID_RESERVATION`、`RESERVATION_EXPIRED`、`MEMBERSHIP_CHANGED`、`IDEMPOTENCY_KEY_REUSED`。一次容量查询最多检查1000条已批准预约，超出409 `CAPACITY_WINDOW_TOO_LARGE`，不截断后伪称完整。资源减量／停用对所有未结束预约执行同一上限保护。

## 离组与后续接入

资源负责人即使资源已停用，也必须先转交再离组。申请人有尚未结束的待审批或已批准预约时先处理。预览隐藏无权查看的预约正文，但保留受限责任数量；预览失败、加载或非零阻断数均不能点击确认。最终退出事务重新检查，预览不是退出许可。

借还接入后必须补未归还实物责任、实物容量和取消保护；拍摄计划接入后补关联安排检查与变动影响；正式变更申请接入前，不开放直接改已批准预约的接口，页面提示取消后重新申请。资源事件暂仅落库，不宣称已经通知相关人。

## 验证范围

自动化验证覆盖半开边界、非同时占用、随机区间与独立穷举结果一致、同组及私有可见查询、权限／范围／负责人独立判定、入组隔离、过期和容量保护、显式授权、原审批证据保留、回执重放、事务提交失败、HTTP安全校验、离组清单，以及前端明确确认、未知结果原键恢复和只读入口。

迁移仅完成离线SQL生成与约束检查；真实PostgreSQL执行、多个进程锁竞争、Redis限流联调、浏览器视觉、性能与可用性验收仍待完成。

本轮新增66项后端、16项前端测试；全量后端508项、前端96项通过，TypeScript检查及Vite生产构建通过。测试使用模拟依赖；容量算法另与独立穷举结果比较。jsdom的伪元素样式提示和现有TestClient弃用警告不影响本轮结果，但不能据此认定真实浏览器或服务联调通过。
