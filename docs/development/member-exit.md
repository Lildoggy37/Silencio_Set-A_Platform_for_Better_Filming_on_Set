# 成员退出与移除

实现范围：本人退出、管理员移除其他成员、末位管理员保护、撤销岗位与例外授权、保留成员历史及事务审计。成员字段沿用现有结构；当前迁移头为 `0008_availability`，最新档期边界见[档期说明](availability.md)。

任务责任查询和清单页面已接入：仍负责或确认未完成任务则阻止离组，有权查看的任务可跳转处理，受限任务只显示数量；任务调整可转交待处理/进行中任务的负责人和确认人。资源预约及拍摄安排交接尚未实现，不能据此宣称全部离组交接已完成。见[通知与交接说明](notifications-and-handover.md)。

## 核心流程

1. 验证登录、昵称完成状态、Origin、CSRF及写入频率限制。成员身份和操作者均来自服务端。
2. 依次取得操作者账号共享锁、剧组协调锁、当前成员锁，在协调锁之后重查当前权限。本人退出只要求仍在组，不要求管理员权限或 `crew.read`；移除他人要求 `member.remove`。
3. 移除目标按同剧组查询并加锁。不能通过移除入口移除自己；跨组或不可访问目标隐藏为404。
4. 检查在组状态、严格整数版本及版本上限；管理员离组必须保留另一名当前账号有效、仍在本组的管理员。
5. 执行已注册责任检查，再使用数据库时间设置 `ended_at`、将状态改为 `left` 或 `removed`、递增成员版本、删除当前岗位及例外授权。成员记录及历史业务引用不删除。
6. 成功审计与上述变更共同提交，提交完成后才返回200。移除原因仅写内部审计，不返回到成员目录或普通应用日志。

邀请接受和岗位修改使用相同的剧组协调锁。离组后业务请求依当前成员状态拒绝；旧会话仍可访问账号本人及其他有权剧组。邀请发送/首次接受会重查邀请人当前资格；旧的已接受凭证不能恢复离组关系。重新加入的旧授权不会恢复，见[邀请说明](invitations.md)。

## HTTP 契约

统一前缀 `/api/v1/crews/{crew_id}`，JSON请求，16 KiB请求体上限，沿用剧组写接口每窗口每IP和用户各10次的共享限制。

| 操作 | 路径 | 必填字段 |
|---|---|---|
| 本人退出 | `POST /members/me/leave` | `expected_lock_version` |
| 移除其他成员 | `POST /members/{member_id}/remove` | `expected_lock_version`、`reason` |

`expected_lock_version` 为1—2,147,483,647的严格整数；不接受布尔值、字符串或额外字段。`reason` 去除首尾空白后1—500个Unicode字符，单行，不含控制字符或孤立代理项。客户端不能传目标状态、岗位、账号标识或操作来源。

200返回 `data.membership`（`id/display_name/status/role_codes/lock_version`）和带时区的 `data.ended_at`。状态分别为 `left` 或 `removed`，岗位数组为空，版本为原值加一。无邮箱、用户ID或移除原因。

| 情况 | 结果 |
|---|---|
| 无组织权限 / 跨组或非当前成员 | 403 `FORBIDDEN` / 隐藏404 `NOT_FOUND` |
| 最后一名有效管理员 | 409 `LAST_ADMIN_REQUIRED` |
| 目标已离组 / 版本冲突 / 版本耗尽 | 409 `MEMBER_INACTIVE` / `VERSION_CONFLICT` / `VERSION_EXHAUSTED` |
| 移除入口选中自己 | 409 `USE_LEAVE_ACTION` |
| 任务检查发现未交接事项 | 409 `MEMBER_HAS_RESPONSIBILITIES`；先转交、完成或取消任务 |
| 数据库失败或提交结果未知 | 503；不声称成功，不自动重放 |

## 页面与未知结果

工作台有“退出当前剧组”；成员目录只对具备移除权限者展示其他成员的移除入口。两种操作均需明确确认，移除原因必填。管理员另行提醒先交接管理员身份；真正保护由后端执行。

成功退出清除当前剧组选择、取消在途剧组查询并清除其缓存，保留登录。移除成功刷新目录及当前权限。网络断开、响应不符合契约或版本冲突后阻止继续提交，须明确读取当前状态，再另行确认；不因刷新或重渲染自动重试。刷新目录找不到目标时，不直接认定移除成功，提示重新选择。

## 后续责任模块的接入要求

`OrganizationRepository(..., exit_checks=...)` 接收异步检查器，每个检查器接收当前事务会话、剧组ID和成员ID。发现阻断项时拒绝；查询失败同样中止，不能把失败当作“没有责任”。应用工厂已注册真实任务检查器，其查询与离组在同一事务中执行。

新增任务/预约/计划模块时必须同时：实现并在应用工厂注册对应查询、定义阻断状态与可处理事项、接入页面提示，并让责任新指派/转交与离组使用同一剧组协调锁且锁后重查在组状态。未来资源审批范围也需随离组撤销。只完成表或CRUD而未接好这条约束，不算该模块完成。

## 验证边界

后端使用模拟会话验证事务、权限与版本分支、同组查询、授权撤销、审计以及检查器阻断和异常；前端以模拟HTTP验证明确确认、最后管理员错误、未知结果读取及版本更新、必填原因和缓存清理。

真实PostgreSQL锁竞争（含两名管理员同时退出）、Redis/RabbitMQ联调、真实浏览器交互和视觉检查尚未执行。单元测试与构建结果不能替代这些验收。
