# 后端主流程：耗材库存与剧本版本

初始批次实现两块后端，随后已补库存与剧本文本版本页面。迁移为`0011_stock`、`0012_scripts`；真实数据库执行、并发联调和文件解析仍待完成。没有操作Docker、读取或调用Qwen密钥。

## 耗材库存

耗材复用`resources`的ID、剧组、负责人、权限范围及离组保护。资源新增`stock_quantity`，耗材的`total_quantity`为空；设备／道具／场地的库存为空。数据库按类型约束数量字段，旧资源不改变语义。

普通资源目录／详情继续返回可复用资源；耗材走独立`consumables`接口，避免现有借还前端误把库存视为预约总量。通用预约、审批与资源修改接口拒绝耗材，借还同样不适用。库存前端、耗材资料编辑和停用入口待补；当前接口覆盖登记与库存账本主流程。

统一前缀`/api/v1/crews/{crew_id}`：

| 方法与路径 | 业务 |
|---|---|
| GET `/consumables` | 剧组成员按资源读取权分页查看余额，页大小至多20 |
| POST `/consumables` | 有资源管理权的制片登记耗材，输入名称、单位、负责人、`initial_quantity`和可空说明；返回201资源与初始化流水 |
| GET `/consumables/{id}/movements` | 有`stock.manage`及该耗材范围者分页读流水 |
| POST `/consumables/{id}/movements` | 版本、`movement_type/quantity_delta/reason`，返回201新余额与流水 |
| PUT `/consumables/{id}/authorization` | 管理员替换指定成员库存经办范围，并可明确转交负责人 |

`restock/return`为正增量，`issue`为负增量，`adjustment`为非零正负差额。初始库存为0时不生成零增量流水。单次输入数量绝对值不超过1000000，余额处于PostgreSQL INTEGER的0—2147483647范围。余额不足或溢出返回409 `STOCK_QUANTITY_CONFLICT`，不部分领用、不偷偷截断。

库存操作按账号／剧组／资源顺序加锁，余额、版本、流水、审计及幂等回执同事务提交；操作键复用资源回执表。流水保留变化量、操作后余额、原因、实际经办人和服务器时间，没有直接覆盖库存的接口。场戏／任务用途关联在相应模块接入后补同组约束，当前不接受任意关联ID。

授权输入沿用经办授权的`member_id/expected_lock_version/expected_member_lock_version/permission_codes/grant_capabilities`，代码只允许`stock.manage`。空集合撤销该资源范围；明确授予才设定能力allow，包括替换deny。`transfer_management=true`同时转交负责人，需管理员、目标成员与资源版本检查，审计记录新旧负责人。转交不自动授予库存能力。这样负责人可以正常完成离组交接，既有经办范围不被隐式清除。

## 剧本版本

先开放明确的文本录入流程，供场戏拆解和Diane读取；本批不是DOCX／PDF导入实现。文本按非空行去首尾空白后生成从1开始的段落，来源页码为空，不编造文件或页码。正文最大100000字符，所有正文以段落为准，没有独立可漂移的全文副本。

前缀`/api/v1/crews/{crew_id}/scripts`：

| 方法与路径 | 业务 |
|---|---|
| GET／POST 集合 | 分页列表／创建剧本，输入title，创建返回201 |
| GET `/{script_id}` | 剧本与当前工作版本正文；尚无工作稿时version为null |
| GET `/{script_id}/versions` | 分页版本摘要，列表不含段落，单条详情才返回正文 |
| POST `/{script_id}/versions` | 剧本版本前提与text，创建待核对版本，返回201；不自动成为工作稿 |
| GET／PATCH `/{script_id}/versions/{version_id}` | 详情／修正待核对正文；修改传版本前提与text |
| POST `/{script_id}/versions/{version_id}/confirm` | 人工确认正文，仅待核对状态可确认 |
| PUT `/{script_id}/working-version` | 剧本版本前提与version_id，仅允许本剧本已确认版本 |

读取要求`script.read`，创建／录入／修正要求`script.edit`，确认与工作稿切换要求`script.confirm`；管理员身份不默认获得创作资料权限。内部业务服务与HTTP共用权限判定，Diane后续调用同一服务。

当前工作版本用同剧组／同剧本复合外键约束。确认后的正文不可覆盖；继续修改须新建版本。更换工作稿与正文确认独立，不自动确认其他资料。场戏、分镜及计划尚未接入，因此当前不宣称已执行来源影响复核；这些模块接入时必须补来源版本及影响事务。

所有写接口使用UUID `Idempotency-Key`，回执按剧组／用户／键摘要唯一，绑定动作、目标、正文摘要及精确入组时间。重放前复核当前权限，离组重新加入不恢复旧回执。剧本写操作沿用剧组协调锁，成功审计只记对象与版本，不把正文写入审计摘要。

所有业务沿用Cookie、Origin／CSRF、限流及禁止缓存。普通业务JSON上限仍16 KiB；仅剧本路由允许至多2 MiB编码后的JSON，以容纳10万字符正文和JSON转义。认证与其他资源接口的上限不变。脚本列表、版本列表每页至多20；正文详情按版本返回完整段落。

文件模块接入后，上传解析的结果也进入待核对版本，补实际文件引用、解析失败状态和页码；当前只开放`pending_check/confirmed`，不伪造parsing／failed任务。后续场戏修订只引用已确认正文，草稿段落修正期间不会承诺引用稳定。

## 库存与剧本页面接入

资源页增加“设备与场地／耗材库存”次级入口。库存页支持分页余额、零库存登记、补充／领用／退回／正负盘点差额、原因与流水，以及管理员指定经办范围、显式授予能力、撤销范围和转交负责人。库存资料改名／单位／停用编辑尚未开放。普通成员只请求余额，不主动读取无权查看的流水。

后端新增GET `/consumables/{id}`；库存DTO补充`allowed_actions=change/authorize`，由当前权限与资源范围决定。变动冲突时保留数量／原因，读取新库存版本后再核对；未知结果明确用原键和原内容重试。离组预览补充`resource_type`，耗材责任跳转库存详情，避免打开可复用资源接口而得到404。

顶部“项目资料”已接剧本库，要求`script.read`。列表、分页版本摘要、单版段落与当前工作稿明确分开；可编辑者创建剧本、录入文本和修正待核对版本，可确认者确认正文和独立切换工作版本。已确认版本隐藏正文修改入口；正文来源页码仍不编造。界面明确DOCX／PDF文件导入、场戏与分镜尚未接入。

前端`api/stock.ts`和`api/scripts.ts`沿用同源HTTP／CSRF、后端契约类型及原生表单输入约束，没有新建逐字段响应校验层。新增9项页面测试覆盖只读、零初始化、负领用、显式授权与转交、草稿保留与版本重读、原键重试、正文确认与工作稿分离，以及确认后不可覆盖。后端新增2项耗材详情权限测试；本轮不新增数据库迁移。

页面批次全量后端574项、前端111项测试通过，TypeScript／Vite构建通过。原布局预览测试已更新为未选择剧组时的资料提示；原请求重试测试在按钮结束加载后再点击，未修改全局超时或产品重试规则。真实浏览器视觉、真实服务联调及文件导入仍待完成。

## 库存权限交互简化

耗材详情增加“库存管理权限”页签，替代“库存经办授权”嵌套弹窗。选择成员与允许／移除修改权限后直接确认保存。允许操作会显式提交 `permission_codes=["stock.manage"]` 和 `grant_capabilities=true`；提交前说明会启用库存操作权限并将已有禁用改为允许，其他耗材仍需对象范围授权。移除仅提交空权限集合，`grant_capabilities=false`，不改变其他耗材授权。负责人转交折叠为可选项，默认不选，移除权限时不转交。

接口、管理员资格、资源与成员版本及幂等键契约保持原样。未知提交结果在同一窗口锁定输入与关闭／切换操作，明确重试原请求；确定版本冲突读取新版本后再提交。授权成功返回库存与流水，显示更新结果。库存变动表单打开时隐藏详情，取消或完成后回到详情。7 项针对性组件检查与前端构建通过；Edge 展示样本检查仅一个对话框，390px 视口无横向溢出，未写入真实库存或权限。
