# Silencio Set · 接口设计

版本：D0.14  
状态：已确认核心业务、Diane、后台任务及邀请接口；补充首次登录完善个人信息，参数和边界测试继续细化。

## 1. 接口统一规范

| 项目 | 规则 |
|---|---|
| 路径 | 统一以`/api/v1`开头；剧组业务位于`/crews/{crew_id}/…`下 |
| 数据格式 | 普通请求和响应使用JSON；文件上传使用`multipart/form-data` |
| 身份认证 | 使用服务端Cookie会话；修改类请求校验CSRF |
| 权限 | 后端验证登录状态、剧组成员身份、操作权限及对象归属，不信任前端传入的身份 |
| 字段命名 | 使用`snake_case`；对象标识使用UUID |
| 时间 | 带时区的ISO 8601格式；页面按Asia/Shanghai展示，时间区间左闭右开 |
| 分页 | 普通列表使用`page`、`page_size`，默认20条、最多100条；排序字段使用白名单 |
| 并发修改 | 修改可变记录时提交`expected_lock_version`；版本过期返回冲突，不覆盖他人修改 |
| 防重复提交 | 发布、审批、借还及Agent执行等接口携带`Idempotency-Key` |
| 异步处理 | 解析、导出、模型调用返回`202`和任务标识，前端查询任务状态 |
| 接口文档 | FastAPI生成OpenAPI，补充业务约束、权限、错误码及示例 |

幂等键绑定用户、操作、目标和请求内容。相同键与相同内容返回已有结果；相同键却改变请求内容返回冲突。幂等键处理重复提交，版本号处理并发覆盖，二者不能互相替代。

## 2. 返回格式与错误处理

成功响应示例：

```json
{
  "data": {
    "id": "对象UUID",
    "lock_version": 2
  },
  "request_id": "请求追踪标识"
}
```

失败响应示例：

```json
{
  "error": {
    "code": "VERSION_CONFLICT",
    "message": "记录已更新，请刷新后重试",
    "details": {
      "current_lock_version": 3
    }
  },
  "request_id": "请求追踪标识"
}
```

示例中的UUID及追踪标识为说明性占位值。采用真实HTTP状态码，不把全部结果包装为`200`。

| 状态码 | 用途 |
|---|---|
| `200 / 201 / 202 / 204` | 成功、创建成功、异步任务已受理、成功且无响应体 |
| `401 / 403` | 未登录或会话失效／无操作权限 |
| `404` | 对象不存在，或需隐藏其存在性 |
| `409` | 版本、状态、资源占用或幂等请求冲突 |
| `413 / 415 / 422` | 上传超限／不支持的文件类型／输入校验失败 |
| `429` | 请求超过限制 |
| `500 / 503` | 内部错误／依赖服务暂不可用 |

错误响应不暴露数据库语句、服务器路径、密钥或内部堆栈。文件下载直接返回文件流，不套用JSON；`204`不返回响应体。

## 4. 页面接口与Agent的关系

页面通过HTTP接口调用业务服务；Diane通过受控工具调用同一业务服务，不必绕行本机HTTP。两条路径都检查权限、版本、状态和资源冲突，不重复实现业务规则。

Agent不能取得任意SQL、任意文件路径访问或绕过审批的能力。人工确认绑定已保存的具体提案，修改提案内容后必须重新确认。

岗位默认权限、代码、可授予范围和各接口对象检查统一见[权限矩阵与接口授权](10_权限矩阵与接口授权.md)。Diane不注册本人档期维护及通知知悉写工具，不能代办这些本人操作。对话私有；他人审批从最小信息提案入口进行，不开放整个对话，分发关联及响应字段仍待细化。

## 5. 注册与登录接口

所有路径省略`/api/v1`。

| 方法与路径 | 主要输入 | 返回与约束 |
|---|---|---|
| `POST /auth/email-verifications` | `email`、`purpose=register` | `202`，返回验证请求标识，不表示邮件已经送达 |
| `POST /auth/email-verifications/verify` | `verification_id`、`email`、`code` | `200`，返回短期`registration_token`及有效期 |
| `POST /auth/register` | `registration_token`、`password` | 首次成功`201`，同一有效凭证成功重试`200`；不覆盖密码、不自动登录，昵称在首次登录后补充 |
| `POST /auth/login` | `email`、`password` | `200`，设置会话Cookie，返回基本用户信息，不返回会话密钥 |
| `POST /auth/logout` | 无业务字段 | `204`，使当前会话失效并清除Cookie |
| `GET /users/me` | 无 | `200`，返回账号基本信息，不返回密码散列 |
| `PATCH /users/me/profile` | `display_name`、`expected_lock_version` | 保存本人昵称并返回个人信息完成状态 |
| `GET /auth/csrf` | 无 | 获取与浏览器会话绑定的CSRF令牌 |

修改请求使用`X-CSRF-Token`；注册、登录等未登录接口也验证来源和预登录CSRF状态。登录后轮换会话与CSRF令牌，防止会话固定。CSRF获取响应禁止缓存，不向任意跨域来源开放凭证读取。

登录失败统一提示“邮箱或密码错误”，不通过错误详情暴露账号状态。验证码、注册凭证、密码及Cookie不进入普通日志。验证码申请按邮箱与IP分别限流，不公开该邮箱是否已注册。验证码有效期、重发间隔、密码长度及会话有效期在安全配置设计中补定。

### 5.1 首次登录补充个人信息

本次用户补充要求替代此前注册必填昵称的设计：注册只验证邮箱并设置密码；首次登录后进入个人信息页，补全昵称后进入剧组功能。昵称沿用`display_name`，去除首尾空白后1—30字，不要求全平台唯一，不采集真实姓名、手机号、学校等额外必填信息，头像暂不纳入本批范围。

登录及`GET /users/me`返回`profile_completed`、`missing_fields`及个人资料版本。未完成时允许获取本人资料、保存资料、获取CSRF及退出；其他受保护业务返回`403 PROFILE_INCOMPLETE`，由后端执行限制，不能只依赖页面跳转。保存昵称与完成状态在同一事务提交；后续登录不重复要求已完成用户填写。个人昵称修改不自动覆盖剧组内显示名或历史快照。

从邀请链接登录时仅在浏览器短期保留待处理邀请，完成资料后继续接受；接受时仍检查有效期、邮箱及邀请状态，补资料不自动加入剧组。验收覆盖首次登录、刷新或重新登录、直接调用业务接口绕过、空白昵称、超长昵称及并发资料修改。

## 6. 剧组与成员接口

以下`C`表示`/crews/{crew_id}`，仍省略`/api/v1`。

| 方法与路径 | 主要输入 | 返回与约束 |
|---|---|---|
| `POST /crews` | `name`、`project_name`、`description` | `201`，同时创建剧组、创建者成员关系及初始管理员授权 |
| `GET /crews` | 分页参数 | 仅返回当前用户所属剧组 |
| `GET C` | 无 | 返回有权查看的剧组信息及当前用户有效权限 |
| `GET C/members` | 分页、成员状态 | 返回成员及岗位，默认展示在组成员；历史成员查看按权限过滤 |
| `PUT C/members/{member_id}/roles` | `role_codes`、`expected_lock_version` | 授权管理员替换岗位集合 |
| `PUT C/members/{member_id}/permission-overrides` | 固定业务权限允许／拒绝项、`expected_lock_version` | 管理员在预定义可授予目录内修改，不以自身业务执行权限作为可授予上限；组织权限只经管理员岗位变更 |
| `POST C/members/{member_id}/remove` | `reason`、`expected_lock_version` | 移除成员并撤销授权，保留历史引用 |
| `POST C/members/me/leave` | `expected_lock_version` | 本人退出，不删除历史记录 |

导演、制片属于业务岗位，不仅凭岗位名称认定其拥有全部管理权限。不允许移除、退出或撤销最后一名有效管理员。成员退出、移除前检查未交接任务及有效安排，返回需要处理的事项，不静默转交责任。成员状态、岗位及例外权限共享成员记录的`lock_version`，每次修改均递增并记录审计；管理员保护还须在剧组协调锁下检查，不能只依赖单条成员版本。

成员加入采用管理员按邮箱邀请、受邀者登录后接受的方式，不凭邮箱直接加入。沿用FR-01规定的7天有效期、可撤销及接受后失效规则。邀请绑定规范化邮箱，接受者的已验证邮箱必须一致；邀请不直接赋予岗位，加入后由管理员授权，重新加入不恢复旧授权。发送、接受、撤销的详细契约在后续接口细化中补充。

## 7. 任务接口

| 方法与路径 | 主要输入 | 返回与约束 |
|---|---|---|
| `POST C/tasks` | 标题、说明、负责人、确认人、截止时间、可选场戏及协作人 | `201`，创建待处理任务 |
| `GET C/tasks` | 状态、负责人、截止时间范围及分页 | 返回授权范围内的任务 |
| `GET C/tasks/{task_id}` | 无 | 返回详情、版本及当前可执行操作；操作提示不替代执行时授权 |
| `PATCH C/tasks/{task_id}` | 允许调整的字段、`expected_lock_version` | 修改基本信息，不接受任意`status` |
| `POST C/tasks/{task_id}/start` | `expected_lock_version` | 负责人将待处理任务转为进行中 |
| `POST C/tasks/{task_id}/submissions` | `completion_note`、`expected_lock_version` | 创建提交记录，同时进入待确认 |
| `POST C/tasks/{task_id}/reviews` | `submission_id`、`decision`、`review_note`、`expected_lock_version` | 指定确认人通过或退回；退回必须说明原因 |
| `POST C/tasks/{task_id}/cancel` | `reason`、`expected_lock_version` | 授权人员取消并保留历史 |

字段类型、必填性及长度沿用《03_核心表字段与约束》第5节。`decision`只接受`accept`或`reject`。待处理、进行中允许授权人员调整基本信息；待确认先处理当前提交，已完成、已取消不直接修改。负责人提交、指定确认人验收，协作人不自动代替二者。

提交、验收和取消携带`Idempotency-Key`。调整负责人或确认人须检查在组状态并通知相关人员。已完成任务重新开展工作时新建任务，首期不增加撤销完成流程。

本批主要业务错误码为`VERSION_CONFLICT`、`INVALID_STATE`、`MEMBER_INACTIVE`、`LAST_ADMIN_REQUIRED`、`HANDOVER_REQUIRED`；均按原因返回冲突或权限错误，不泄露其他剧组信息。

## 8. 文件上传与访问

以下`C`表示`/api/v1/crews/{crew_id}`。

| 接口 | 主要输入 | 返回与约束 |
|---|---|---|
| `POST C/files` | 文件、用途`purpose` | `201`，返回文件ID、类型及大小，不返回服务器路径 |
| `GET C/files/{file_id}` | 无 | 返回有权查看的元数据 |
| `GET C/files/{file_id}/content` | 无 | 鉴权后返回文件流；照片可预览，文档默认下载 |

用途区分剧本与勘景照片，分别校验上传权限、类型及大小。剧本支持DOCX、文本型PDF、TXT，上限20×1024×1024字节，正文上限100000字符。检查实际格式，不只检查扩展名，不执行文档脚本或外部链接。上传成功不代表解析成功。访问同时检查所属剧组、关联业务及当前权限，不仅凭文件ID下载。首期不提供任意文件删除接口。照片格式及大小限制在勘景页面设计中确定。

## 9. 剧本与版本接口

| 接口 | 主要输入 | 返回与约束 |
|---|---|---|
| `POST C/scripts` | `title` | `201`，创建剧本，尚无工作版本 |
| `GET C/scripts` | 分页 | 返回剧本及工作版本摘要 |
| `POST C/scripts/{script_id}/versions` | 输入方式、源文件ID或粘贴正文、版本说明 | `202`，返回版本及解析任务ID |
| `GET C/script-versions/{version_id}` | 无 | 版本信息、解析状态及失败原因 |
| `GET C/script-versions/{version_id}/paragraphs` | 分页 | 按编号返回正文 |
| `PUT C/script-versions/{version_id}/paragraphs` | 完整有序段落、`expected_lock_version` | 仅待检查状态允许整体修正 |
| `POST C/script-versions/{version_id}/confirm` | `expected_lock_version` | 确认并冻结正文 |
| `PUT C/scripts/{script_id}/current-version` | 已确认版本ID、`expected_lock_version` | 切换工作版本，提示关联影响 |

文件与粘贴正文二选一，来源文件须同剧组且有权使用。确认正文与选择工作版本分开，确认历史稿不自动替换工作稿。剧本及待检查版本各自使用`lock_version`，避免修正文稿及切换版本时互相覆盖。正文编号变化必须复核引用，不能留下失效引用；确认后的正文不可原地覆盖。

## 10. 场戏与拆解接口

| 接口 | 主要输入 | 返回与约束 |
|---|---|---|
| `GET C/scenes` | 剧本、拆解版本及分页 | 查询指定版本下的场戏，不混合历史稿 |
| `POST C/scene-breakdowns` | 已确认剧本版本ID | 创建人工拆解草稿 |
| `POST C/scene-breakdowns/{breakdown_id}/scenes` | 编号、地点、时段、原文引用等 | 新建场戏或明确关联已有稳定场戏 |
| `PATCH C/scene-revisions/{revision_id}` | 修改字段、`expected_lock_version` | 仅草稿可修改 |
| `POST C/scene-breakdowns/{breakdown_id}/submit` | `expected_lock_version` | 整份送审，检查编号与引用 |
| `POST C/scene-breakdowns/{breakdown_id}/reviews` | 通过／退回、说明、`expected_lock_version` | 授权人员审核，退回须说明原因 |
| `POST C/scene-breakdowns/{breakdown_id}/reopen` | `expected_lock_version` | 仅已否决整份恢复草稿，有编辑权限，所属修订同步恢复并递增版本 |

一份拆解对应一个剧本版本和一组明确场戏修订。新旧场戏身份由用户选择，不仅按编号自动匹配。原文片段由后端根据段落范围取得，不信任客户端自行提交的引用原文。剧情地点不等于落实拍摄场地。已确认拆解不原地修改，计划引用确定修订。

## 11. 文字分镜接口

| 接口 | 主要输入 | 返回与约束 |
|---|---|---|
| `POST C/storyboards` | `scene_id` | 创建稳定分镜稿对象 |
| `POST C/storyboards/{storyboard_id}/versions` | 来源修订、可选复制来源版本 | 创建可编辑草稿 |
| `GET C/storyboard-versions/{version_id}` | 无 | 来源、审核状态、版本及有序镜头 |
| `PUT C/storyboard-versions/{version_id}/shots` | 完整镜头列表、`expected_lock_version` | 整体保存并检查镜号、顺序及字段 |
| `POST C/storyboard-versions/{version_id}/submit` | `expected_lock_version` | 送审 |
| `POST C/storyboard-versions/{version_id}/reviews` | 通过／退回、说明、`expected_lock_version` | 授权人员确认或退回 |
| `POST C/storyboard-versions/{version_id}/reopen` | `expected_lock_version` | 有编辑权限者显式将已否决版本恢复草稿 |

首期整份分镜一次保存，不提供实时多人协同编辑，通过版本检查避免覆盖。已确认分镜修改时创建新版本，不自动改变已发布计划。Diane后期生成的场戏与分镜也进入草稿、修改、审核流程，不能直接生成已确认资料。

审核决定统一取`accept`或`reject`。本批主要错误包括文件类型不支持、正文超限、版本冲突、来源不匹配、引用失效、编号重复及状态不允许修改；分别映射415、413或422、409等状态，失败信息不暴露内部解析堆栈。

两类创作审核统一`draft→pending_review→confirmed`；退回进入`rejected`，只能经`reopen`回到`draft`。待审禁止编辑，确认后不能reopen。审核携带幂等键并保存审核历史及被审内容快照；恢复编辑不覆盖历史。重新打开成功返回200及新版本，旧版本、重复无效状态请求返回409，不重复迁移；无权403或按隐藏策略404。并发审核及编辑按所属拆解／分镜版本协调，Diane不能跳过以上状态。

## 22. 核心接口详细契约：资料、预约与计划

### 22.1 公共请求及失败约定

以下路径均含`/api/v1`，普通JSON响应使用第2节外层格式。受保护修改请求验证Cookie会话、`X-CSRF-Token`及适用来源；业务状态由后端写入，不接受客户端指定操作者、审核人或成功状态。

要求幂等键的接口缺少`Idempotency-Key`返回`422 VALIDATION_ERROR`。同键同内容定位原结果，同键异内容返回`409 IDEMPOTENCY_KEY_REUSED`；返回既有结果前仍校验当前访问权，不因历史操作而永久可读。错误详情按当前权限过滤，不泄露其他成员无关记录。

### 22.2 补全或修改昵称

`PATCH /api/v1/users/me/profile`，需要登录，不要求资料已完成。

| 字段 | 类型与必填 | 校验 |
|---|---|---|
| `display_name` | 字符串，是 | 去除首尾空白后1—30字，可重名 |
| `expected_lock_version` | 正整数，是 | 当前本人资料版本 |

成功200示例：

```json
{
  "data": {
    "display_name": "林同学",
    "profile_completed": true,
    "missing_fields": [],
    "lock_version": 2
  },
  "request_id": "req_example"
}
```

账号由会话确定，不接收他人账号ID。首次填写昵称与完成时间同事务提交，后续改昵称不重置首次完成时间。失败为`401 SESSION_EXPIRED`、`422 VALIDATION_ERROR`或`409 VERSION_CONFLICT`，不覆盖已生效内容。

### 22.3 预约审批

`POST /api/v1/crews/{crew_id}/resource-reservations/{reservation_id}/decisions`，要求幂等键。

| 字段 | 类型与必填 | 校验 |
|---|---|---|
| `decision` | 枚举，是 | `accept`或`reject` |
| `decision_note` | 字符串，拒绝时必填 | 不超过500字，拒绝原因不可空白 |
| `expected_lock_version` | 正整数，是 | 当前预约版本 |

同组、在组、具有`reservation.review`且为资源当前负责人，才可操作待审批预约；批准按统一锁顺序在事务内检查状态及时段峰值，不依据页面余量。

成功200示例：

```json
{
  "data": {
    "reservation_id": "11111111-1111-4111-8111-111111111111",
    "status": "confirmed",
    "lock_version": 2
  },
  "request_id": "req_example"
}
```

拒绝成功时状态为`rejected`，同样递增版本、保留实际审核人及时间。数据库审批标识与幂等结果同事务保存；拒绝也须可幂等恢复，不仅批准防重复。

| HTTP／错误码 | 原因 |
|---|---|
| `403 FORBIDDEN` | 无审批权限或不是当前资源负责人 |
| `404 NOT_FOUND` | 不存在或不属于可访问范围 |
| `409 VERSION_CONFLICT` | 预约版本变化 |
| `409 INVALID_STATE` | 已处理或已取消 |
| `409 RESOURCE_UNAVAILABLE` | 批准时资源停用或不可用 |
| `409 RESOURCE_CAPACITY_CONFLICT` | 批准后时段占用超量 |
| `409 IDEMPOTENCY_KEY_REUSED` | 同键异内容 |
| `422 VALIDATION_ERROR` | 字段类型、长度或枚举非法 |

### 22.4 预检输出及计划发布

预检`POST /api/v1/crews/{crew_id}/plan-versions/{version_id}/preflight`接收`expected_lock_version`。成功200的`data`含`checked_data_revision`（后端不透明检查标记）、`blockers`（阻断清单）、`unknown_items`（未知档期清单）。每个未知项含`item_id`、`member_id`、`session_id`、`starts_at`、`ends_at`，仅列缺失区间，页面逐项展示且默认不勾选。预检完成不保证发布许可。

发布`POST /api/v1/crews/{crew_id}/plan-versions/{version_id}/publish`要求幂等键和`plan.publish`。

| 字段 | 类型与必填 | 校验 |
|---|---|---|
| `expected_lock_version` | 正整数，是 | 当前草稿版本 |
| `expected_current_published_version_id` | UUID或null，是 | 首次发布明确传null，不能省略比较 |
| `checked_data_revision` | 非空字符串，是 | 绑定本成员、本剧组、本草稿的预检标记 |
| `confirmed_unknown_item_ids` | 不重复字符串数组，是 | 与当前预检未知项集合完全对应；没有未知项传空数组，拒绝额外或失效项 |

不能传`force=true`忽略阻断。发布事务重新检查权限、草稿、原当前版本及所有冲突依据，校验检查标记及确认集合；变化后要求重新预检。标记生成和持久记录见D03第18.1节。

成功200的`data`包含`published_version_id UUID`、`status=published`、`lock_version`、`previous_published_version_id UUID或null`、`affected_call_sheet_version_ids UUID数组`及`notification_status=pending_dispatch`。通知状态描述本次受理结果，不表示成员收到，重复请求的业务结果稳定，实时投递状态通过对应查询获取。

| HTTP／错误码 | 原因 |
|---|---|
| `401 SESSION_EXPIRED`、`403 FORBIDDEN`或`404 NOT_FOUND` | 身份、权限或访问范围不满足 |
| `409 VERSION_CONFLICT` | 草稿变化 |
| `409 CURRENT_VERSION_CHANGED` | 其他请求已发布新版 |
| `409 PREFLIGHT_STALE` | 标记无效、过期或检查依据变化，需重新预检 |
| `409 UNKNOWN_CONFIRMATION_REQUIRED` | 未完整确认当前未知档期项 |
| `409 PLAN_BLOCKED` | 已知时间冲突、资源未落实或来源无效 |
| `409 INVALID_STATE` | 不是可发布草稿 |
| `409 IDEMPOTENCY_KEY_REUSED`、`422 VALIDATION_ERROR` | 幂等键冲突或非法字段 |

发布失败不切换正式版本，不保存半份结果。已经成功的同键重试在当前访问校验后返回原提交结果，先定位已完成幂等结果，不因首次提交后预检、状态或版本已变化而误判为再次发布冲突。等待其他正在执行的同键请求时只返回可识别的处理中或受控冲突，不并行执行第二次。

## 23. 核心接口详细契约：通告与提案

本节路径省略`/api/v1/crews/{crew_id}`，沿用第22.1节会话、CSRF、幂等、错误脱敏及结果恢复约定。身份失效返回401，无权403或按隐藏策略404，非法输入422；幂等同键异内容409。

### 23.1 保存通告接收人

`PUT …/call-sheet-versions/{id}/recipients`，要求`call_sheet.edit`。

| 字段 | 类型／必填 | 规则 |
|---|---|---|
| `member_ids` | UUID数组，是 | 不重复，同组且当前在组，必须覆盖来源场次全部必选成员 |
| `expected_lock_version` | 正整数，是 | 当前通告版本 |

成功200的`data`含`required_member_ids UUID数组`、`optional_member_ids UUID数组`、`status`及新`lock_version`。二者分别表示本次保存的必选和额外已选成员，不是全剧组可选人员列表。

草稿允许修改，已审核修改后回到草稿并重新审核；待审核和已发布不得直接修改。失败不部分保存。字段、重复ID错误为`422 VALIDATION_ERROR`；遗漏必选为`409 REQUIRED_RECIPIENT_MISSING`，已退出为`409 RECIPIENT_INACTIVE`，版本或状态问题为`409 VERSION_CONFLICT`／`409 INVALID_STATE`。跨组或不可访问成员按隐藏策略拒绝，不泄露所属组及私人资料。

### 23.2 审核通告

`POST …/call-sheet-versions/{id}/reviews`，要求`call_sheet.review`及`Idempotency-Key`。

| 字段 | 类型／必填 | 规则 |
|---|---|---|
| `decision` | 枚举，是 | `accept`或`reject` |
| `review_note` | 字符串，退回必填 | 不超过500字，退回原因不可空白 |
| `expected_lock_version` | 正整数，是 | 当前待审核版本 |

成功200的`data`含`review_id UUID`、`status`及新`lock_version`；通过为`approved`，退回为`draft`。不接收审核人ID，后端从实际身份写入。审核绑定正文、来源及接收集合，保留审核快照；内容或集合改变使原通过结论失效。

主要错误为403／404、`409 VERSION_CONFLICT`、`409 INVALID_STATE`、`409 IDEMPOTENCY_KEY_REUSED`及422。旧审核记录不因重审覆盖，重复同键返回原结果，不再生成另一条审核记录；其他新请求不能重新审核已经完成决定的当前轮次。

### 23.3 发布通告

`POST …/call-sheet-versions/{id}/publish`，要求`call_sheet.publish`及`Idempotency-Key`。

| 字段 | 类型／必填 | 规则 |
|---|---|---|
| `expected_lock_version` | 正整数，是 | 当前已审核通告版本 |
| `expected_current_published_version_id` | UUID或null，是 | 首次发布显式null，不能省略当前指针比较 |

发布事务检查来源仍是当前有效发布计划、内容及接收集合仍对应有效审核、接收人在组且必选完整、原当前通告版本未变。发布、接收快照、审计及Outbox同事务保存，失败整体回滚。

成功200的`data`含`published_version_id UUID`、`status=published`、`validity_status=valid`、`lock_version`、`recipient_count`非负整数及`notification_status=pending_dispatch`，只表示发布和投递受理，不表示送达或知悉。实时投递状态另查，原请求重试不重发新业务事件或清除回执。

| HTTP／错误码 | 原因 |
|---|---|
| `409 SOURCE_PLAN_STALE` | 来源计划已更新或不再有效 |
| `409 REVIEW_REQUIRED` | 未审核或原审核已失效 |
| `409 RECIPIENT_SET_INVALID` | 在组、必选覆盖或审核接收集合不再满足 |
| `409 CURRENT_VERSION_CHANGED` | 其他人已切换当前发布版本 |
| `409 VERSION_CONFLICT` | 内容或状态版本变化 |
| `409 INVALID_STATE` | 目标不处于可发布状态 |

另适用第22.1节通用身份、输入及幂等错误。已经成功的同键请求优先定位原结果，仍检查当前读取权，不按首次发布后的版本变化再次执行或误判重放为新发布。

### 23.4 确认或拒绝Diane提案

`POST …/proposals/{id}/decisions`，要求`Idempotency-Key`，按实际拟执行动作检查业务权限及目标范围；不以仅有查看权或`diane.use`作为批准依据。

| 字段 | 类型／必填 | 规则 |
|---|---|---|
| `decision` | 枚举，是 | `accept`或`reject` |
| `expected_lock_version` | 正整数，是 | 用户所见提案版本 |
| `decision_note` | 字符串，否 | 不超过500字 |

拒绝成功200的`data`含`proposal_id UUID`、`status=rejected`及新`lock_version`，不产生拟议业务变更。接受成功202的`data`含`proposal_id UUID`、`run_id UUID`、`status=confirmed`、`resume_job_id UUID`、`resume_job_status=pending_dispatch`及新`lock_version`。表示确认和恢复任务已持久受理，不是已执行成功；真实调度、执行状态由查询接口获取。

为区分受理和执行，提案新增`confirmed`状态表示已确认待调度，Worker实际取得执行权后才进入`executing`。确认记录、恢复任务及Outbox同事务保存，Broker故障不撤销已持久受理，数据库提交失败不能返回202。原对话当前执行仍绑定同一run，等待后续调度而不让新请求抢先改写上下文。

不接收拟议操作的新内容、任意工具名或确认人ID；额外未定义修改字段拒绝。确认时检查有效性，Worker执行时再次检查，排队期间撤权、目标变化可使提案失效并停止；不自动生成和批准替代提案。

失败为`403 FORBIDDEN`或隐藏404，`409 PROPOSAL_INVALIDATED`、`409 VERSION_CONFLICT`、`409 INVALID_STATE`、`409 IDEMPOTENCY_KEY_REUSED`及422。相同键重试返回原决定受理结果，不重复创建恢复任务；不同键对已决定对象再次决定返回状态冲突，拒绝与接受并发仅一项有效决定。查看及恢复必须保持最小披露，私有对话不因他人确认而公开。

## 24. 内部服务与外部适配契约

### 24.1 内部业务服务

以下为Python模块内的逻辑接口，不新增HTTP微服务。命名用于表达职责，具体方法及类型在初始化时实现并锁定，不宣称已有代码。

| 入口 | 输入 | 输出与责任 |
|---|---|---|
| `TaskService` | 可信操作上下文、任务参数、版本及幂等键 | 任务／提交结果；权限、状态及事务 |
| `ResourceService` | 上下文、资源或预约引用、审批或借还参数 | 实际结果；负责人、范围、容量及数量 |
| `PlanService` | 上下文、草稿、预检标记、确认集合 | 冲突或发布结果；协调锁及版本切换 |

基础设施适配器不自行提交正式业务；数据库事务不等待模型、邮件或人工确认。Worker恢复重建当前授权，不永久沿用入队权限。权限、版本及业务冲突不以整层自动重试掩盖。

### 24.2 Qwen模型适配

拟采用百炼兼容Chat接口，经LangChain适配供LangGraph调用；具体模型ID、地区及服务地址按实际账号验证，`Qwen 3.7`是已选模型方向，不当作已确认可用API标识。配置引用已有`QWEN_BASE_URL`、`QWEN_MODEL`及`QWEN_API_KEY`，前端及模型不能指定任意目的地址。兼容接口字段依据[阿里云官方说明](https://www.alibabacloud.com/help/en/model-studio/qwen-api-via-openai-chat-completions)，具体版本及工具能力实施时复核。

`ModelAdapter.generate()`逻辑输入：

| 字段 | 类型与约束 |
|---|---|
| `messages` | 消息列表，只含按当前权限筛选的必要上下文 |
| `allowed_tools` | 固定目录中本轮允许工具及参数结构，不是任意可执行工具名 |
| `model_config_ref` | 后端受控模型配置引用，不接收客户端密钥或任意URL |
| `output_limit` | 后端预算允许的正整数输出上限，按已验证模型能力映射 |
| `deadline` | 当前调用截止信息，受整次执行剩余预算约束 |
| `run_id`、`call_id` | 稳定执行及本次调用标识，重试另记实际尝试 |

统一输出`content`、`tool_calls`、`finish_reason`、`usage`、实际模型标识、服务请求标识及起止时间。工具调用仅为建议，由编排及业务服务校验后执行，不能把返回`tool_calls`显示为已完成业务。内部推理不作为普通用户输出或普通日志保存。

`usage`保留实际输入、输出及服务提供的分类用量，缺失为空，估算与实测分开。结束原因区分正常结束、工具请求、截断及异常；截断或非法工具参数不能当完整成功。并行返回或流式分段按实际调用聚合，不能重复计量同一最终usage。

错误分类为认证／配置错误、限流、网络超时、服务故障及非法响应；只有适用暂时故障有限重试。模型适配层承担该次模型请求重试，关闭或协调SDK重复策略，Celery不得整体重放已完成业务来重试一条模型回答；各次尝试计入时间和用量。具体模型及服务额度未验证时不开放Diane为可用功能。

### 24.3 邮件适配

首期依据现有`MAIL_HOST`、`MAIL_PORT`、`MAIL_USERNAME`、`MAIL_PASSWORD`及`MAIL_FROM`配置采用SMTP适配，不绑定邮箱品牌。传输安全、证书校验及服务实际认证方式在实施时验证，凭据不进前端或日志。

`MailAdapter.send()`输入为受控模板类型（验证码或剧组邀请）、单个收件地址、模板参数或短期敏感载荷引用、消息标识、有效期及发送截止信息。不接受任意用户自定义邮件模板或批量营销内容。

| 输出状态 | 含义及处理 |
|---|---|
| `accepted` | 邮件服务已接受，不等于用户收到；记录可获得的服务标识及时间 |
| `rejected` | 明确拒绝，返回脱敏类别，按是否暂时故障决定有限重试 |
| `unknown` | 连接中断等导致接受结果不明，保留未知，不直接宣布从未发送或无界重发 |

验证码及邀请原始凭证不放入RabbitMQ、普通日志或长期任务结果。使用D03第2.2.1节短期加密载荷，任务只引用不透明标识；Worker读取后再次检查用途、有效期和当前请求，再调用适配器。已失效则停止，载荷过期或丢失返回明确失败，由用户按规则重新申请，不从摘要反推验证码或凭证。

发送检查与远端SMTP不是同一事务；发送中发生重发或撤销，已在途旧邮件仍可能到达，但旧码或凭证不能再验证成功。服务接受后本地响应丢失也可能形成重复邮件，不承诺SMTP严格只发送一次。未知结果与明确失败分开，重发仍受验证请求、有效期及次数限制。

本地测试使用邮件替身验证模板和状态，不向无关地址发送；真实SMTP认证、传输与服务接受另行测试，不将测试适配器返回成功等同真实送达。模型模拟与真实Qwen测试同样分报。

## 25. 资源范围、提案分发与任务执行权

### 25.1 资源授权范围

资源维护、审批、借还与库存入口除权限代码外校验D03第12.3节范围。制片默认维护本组资料，工作人员不得自行扩大范围；批准额外要求当前资源负责人。管理员可通过`PUT /api/v1/crews/{crew_id}/resources/{id}/scope-grants`明确替换授权集合，输入为成员与固定权限代码的`grants`数组及`expected_lock_version`，仅`member.authorize`可操作。

授权只限定已具备业务权限者的资源范围，不自动给成员新增岗位或全局业务代码；缺少有效权限、类型不适用、重复组合或跨组引用拒绝。成功200返回授权集合及新资源版本；字段非法422，版本冲突409，无组织权403或隐藏404。资源负责人交接与范围、权限共同检查，旧负责人范围撤销后立即停止批准，Worker执行同样重检。

### 25.2 分发提案给确认人

`PUT /api/v1/crews/{crew_id}/proposals/{id}/reviewers`。

| 字段 | 类型／必填 | 规则 |
|---|---|---|
| `reviewer_member_ids` | 不重复UUID数组，是 | 仅同组在组、对实际必要动作及对象具有权限和责任的成员 |
| `expected_lock_version` | 正整数，是 | 当前提案版本 |

仅创建者可为尚未决定的本人提案更改分发集合，必须仍有访问权；后端校验候选资格，不因创建者选择而授予批准权。成功200返回提案ID、已选确认人及新`lock_version`。非法字段422，无权403或隐藏404，版本冲突`409 VERSION_CONFLICT`，已决定`409 INVALID_STATE`，候选失效`409 REVIEWER_INELIGIBLE`，详情不泄露无权成员信息。

创建者从本人对话查看提案，他人从独立待确认入口查看已分发且当前仍有权的提案最小详情；不开放私有聊天。多名候选中任一符合条件者一次有效接受或拒绝即可，决定后停止其他决定和集合修改。未被分发的他人即使有业务权限也不能自行读取私人提案；被分发者若失权同样拒绝。结果引用再按当前业务权限过滤，不形成永久数据访问权。独立待确认列表见第27.1节。

### 25.3 后台执行权

租约、心跳及token为内部协调，不对前端暴露可续租或接手接口。Worker按D03第25节条件取得执行权，API及工具不信任请求中自报worker_id或token。旧执行不能更新新执行的心跳、结果或终态；稳定业务键继续防重复，不以租约代替业务幂等。人工等待释放当前阶段，外部结果不明不因换Worker盲重放。

## 26. 影响提醒、通告模板及照片输入边界

### 26.1 变更影响

业务对象详情或预检关联D03第29节的检查状态和当前问题，返回问题类型、获授权的触发／目标引用、版本、检查时间及可处理入口。待检查或失败不能包装为全部就绪。读取按目标资料权限过滤；正式发布仍实时检查，不以问题列表空作为保证。

问题只能在重检或有权复核并确认依据后解除，不开放“标为已读即解决”的写接口。源版本待复核须明确记录对应工作版本与旧关联；具体请求见第27.3节，不改变现有版本不可覆盖规则。

### 26.2 通告模板

`PATCH …/call-sheet-versions/{id}`可修改`gathering_at`、`gathering_location`、`contact_note`、`notes`并提交`expected_lock_version`。时间为带时区ISO 8601，地点最多300字、联络说明500字、备注2000字；可选字段允许null，草稿允许未填完，送审及发布必须有有效集合时间和非空地点。集合不得晚于第一场开始，跨日显示完整日期。

项目名称、拍摄日期、业务版本及场次时间、场地、参与人由确定来源形成快照，不接收通告请求反向改写安排。网页和PDF读取同一确定版本及快照，不分别拼装不同内容；不新增模板编辑器。字段超限或类型非法422，送审／发布缺完整内容按422说明字段，来源或版本状态冲突409，原有审核及重审规则不变。

### 26.3 勘景照片

上传`purpose=location_photo`，实际格式为JPEG、PNG或静态WebP，单文件≤10485760字节，解码像素≤25000000；拒绝SVG、动图、HEIC和损坏文件，返回明确转换或重新上传提示。大小超限413、格式不支持415，损坏或像素非法422。规范方向并清除EXIF定位等元数据后生成可访问展示文件，处理未成功不声明available。

关联场地时照片说明最多500字、当前有效关联最多20张，按资源版本及锁重检数量；并发越限返回409，不因上传本身成功而绕过关联限制。文件私有鉴权，不默认给模型。孤立或失败临时文件按安全清理规则处理，不删已引用文件；具体解码资源及处理时限待测，以上为设计初值而非性能证明。

## 27. 提案列表与影响问题复核契约

### 27.1 提案列表

`GET /api/v1/crews/{crew_id}/proposals`接收`scope=created_by_me|assigned_to_me`、`status`及统一`page/page_size`，scope必填，status默认`pending_confirmation`。返回200，`data.items`包含提案ID、动作类型、简要影响、状态、lock_version、created_at及can_decide，另返回分页信息。

创建者只读本人提案；分发列表同时检查有效分发、当前在组及动作权限，不能凭历史接收永久可读。can_decide只是显示提示，提交时重新校验。无数据返回空数组，不同于请求失败；不返回聊天、推理及无关工具结果。页面为Diane的待我确认次级入口，不新增一级导航。非法筛选422，身份／范围按401、403或隐藏404处理。

### 27.2 影响问题查询与重新检查

`GET /api/v1/crews/{crew_id}/impact-issues`支持issue_type、status、固定类型目标及ID、分页；按目标资料权限过滤。返回200及问题列表、问题／目标版本、当前状态、检查状态、最近检查时间与处理入口；列表空不等于检查已完成，另返回相应检查范围状态，不展示未授权触发详情。

`POST …/impact-issues/{id}/recheck`输入`expected_lock_version`，要求原目标编辑、管理或审核权限及`Idempotency-Key`；成功202返回问题ID、检查job_id和受理状态。仅请求重新检查，不直接解除问题，修改检查修订及创建任务、Outbox同事务提交。重复同键返回同一任务，针对同一当前检查修订合并待执行请求；超出频率返回429，不无界堆积。版本变化409，字段非法422，授权401／403／隐藏404。

### 27.3 来源人工复核

`POST /api/v1/crews/{crew_id}/impact-issues/{id}/source-reviews`，要求幂等键，首期仅`source_review_required`且目标为场戏修订或分镜版本；分别检查scene.review或storyboard.review及同组来源访问权。

| 字段 | 类型／必填 | 规则 |
|---|---|---|
| `expected_lock_version` | 正整数，是 | 当前问题版本 |
| `expected_current_script_version_id` | UUID，是 | 用户实际核对的当前工作稿 |
| `conclusion` | 枚举，是 | `still_applicable`或`needs_revision` |
| `review_note` | 字符串，是 | 去首尾空白后1—1000字，说明核对依据 |

成功创建201返回review_id、问题ID及当前问题状态。still_applicable只有在事务内重检当前工作稿、目标和依据仍有效后解除本来源问题；needs_revision记录结论并保留open，引导创建新版。问题与工作稿变更按统一协调锁协调，审核记录、依据及问题结果同事务保存。同键重试返回原记录，不重复复核。

复核不改原始来源、不确认草稿、不修改正式计划，不免除其他问题。`409 SOURCE_VERSION_CHANGED`表示工作稿再次变化，另有409 VERSION_CONFLICT／INVALID_STATE／ISSUE_TYPE_UNSUPPORTED、403或隐藏404、422；资源不足、档期冲突或失效通告不能调用该接口强行忽略。

## 28. 后续细化

按模块补充输入、输出、权限、错误码和调用限制；涉及数据字段或业务规则补充时同步相关设计，不以接口设计静默改变既有需求。
