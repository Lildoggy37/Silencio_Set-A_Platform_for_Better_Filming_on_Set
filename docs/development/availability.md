# 本人档期与授权查看

本阶段实现：本人按范围读取/替换可用与不可用区间、未知时段展示、导演/制片等授权人员分页只读查看，以及成员页和排期页入口。本阶段迁移`0008_availability`；最新迁移与后续资源实现见[资源与预约](resources-and-reservations.md)。

拍摄计划、冲突预检和已发布安排复核尚未实现，因此响应明确返回`plan_review_status=not_implemented`，不返回“影响0项”或声称已完成计划复核。真实PostgreSQL迁移、排斥约束与锁竞争、容器联调和浏览器视觉验收仍待补；本轮未处理Docker。

## 2. 范围替换与并发

区间统一为`[starts_at, ends_at)`，相邻边界不重叠，允许跨日。只有`available/unavailable`两种已登记状态；未登记是补集，不能默认为可用。

保存仅替换所选范围：删除与范围相交的旧记录，跨左/右边界时保留相应范围外片段，再写入新集合。范围外完全不相交的记录不变。范围内省略部分恢复为未知，空数组清除该范围。前端明确核对替换范围、条数及清除含义后才提交。

写入顺序：当前账号共享锁 → 剧组协调锁 → 锁后重查成员及`availability.self` → 档期集合锁 → 版本/入组前提检查 → 替换区间、递增集合版本及成功审计 → 共同提交。无条目也保留集合版本，不通过删除集合来重置并发控制。首次GET不创建记录，无集合时返回初始版本1；首次写入成功返回2。

读取把成员、集合版本与区间放在同一个SQL快照，刷新已在ORM会话加载的实体，避免将旧版本和新区间拼接。读取范围内的区间按边界裁剪，前端基于该范围编辑，保存时后端仍保留范围外片段。

入组前提`expected_membership_joined_at`使用本人接口返回的原始带时区时间，精确保留微秒，不经浏览器Date重新格式化。离组重新加入后，旧集合内容不对当前入组显示；集合版本不重置。旧页面持旧入组时间提交409 `MEMBERSHIP_CHANGED`。当前入组首次明确保存时，清除该成员旧入组的隐藏登记并开始新集合内容，审计标注入组重置。

## 3. 权限与HTTP

前缀`/api/v1/crews/{crew_id}`。本人维护须当前在组、昵称完整及`availability.self`；查看剧组须`availability.read_all`，默认导演/制片。管理员身份本身不获得全组档期；明确拒绝参与有效权限计算。没有按任意成员ID写入的接口，Diane不注册此写工具。

| 方法与路径 | 输入与结果 |
|---|---|
| GET `/members/me/availability` | 必填查询`range_start/range_end`；返回本人集合版本、登记及未知补集 |
| PUT `/members/me/availability` | `range_start/range_end/expected_lock_version/expected_membership_joined_at/intervals`全部必填；200本人新版本 |
| GET `/availability` | 必填查询范围，分页及可选`member_id`；授权人员只读当前在组成员 |

`intervals`每项为`starts_at/ends_at/availability`，不接受成员ID、用户ID、任意状态或额外字段。时间为带时区ISO格式，登记及范围按整秒，后端统一UTC；页面按北京时间展示。入组时间作为独立前提保留完整精度。版本为1—2,147,483,647严格整数，拒绝布尔及字符串。

响应包含`member_id/display_name/membership_joined_at/lock_version/updated_at/range_start/range_end/intervals/unregistered/plan_review_status`，不返回私人邮箱或账号ID。旧入组或无集合时显示全部未知，`updated_at=null`。剧组响应按成员分页，每个成员使用相同窗口。

首期工程边界：窗口大于0且至多31天；单次输入至多100段；本人读取至多500行、每页剧组读取至多1000行；当前每成员存储上限2000段。超过读取上限返回409 `AVAILABILITY_WINDOW_TOO_DENSE`，不截断成完整结果；超存储上限409 `AVAILABILITY_CAPACITY`，不执行删除。页面超过100段时只展示并要求缩小范围后编辑。剧组页大小1—20、页码1—100000，按入组时间/成员ID稳定排序，区间按起点/ID排序。

沿用16 KiB JSON体上限、Origin/CSRF、无缓存响应、每窗口每IP/用户读120次与写10次限制。未知结果和旧版本均先读取，不自动重放PUT。

## 4. 数据约束与迁移

`member_availability_sets`以`crew_id/member_id`为复合主键，保存`membership_joined_at/lock_version/updated_at`，复合外键限制成员同组。`member_availability`包含UUID主键、相同成员范围、起止、可用状态、行版本及时间，通过集合复合外键约束所属范围。

PostgreSQL检查结束晚于开始、固定状态、正版本；GiST排斥约束按剧组、成员及`tstzrange(...,'[)')`禁止任何登记重叠。迁移会执行`CREATE EXTENSION IF NOT EXISTS btree_gist`，真实迁移账号需要相应扩展创建权限。回滚表时保留扩展，避免删除其他模块共享能力。本轮只生成离线SQL并检查结构，尚未验证真实扩展安装和数据库执行。

## 5. 页面恢复与后续接入

“我的档期”可编辑，“剧组档期”只读并可仅查看某成员。新时间段必须明确填写时间与状态，不自动把未知变为可用。切换查询范围的按钮明确会替换草稿。保存前展示核对步骤，空集合另提示清除。

发生冲突、入组变化或网络结果未知时保留草稿、停止提交；“读取当前档期并保留草稿”只更新比较基线，不自动采用新内容覆盖输入。当前登记与草稿相同时无须再次保存，仍不把未知响应归因为确认成功。后台读取发现版本变化也提示核对并阻止沿用旧基线。已确认保存不因只读视图刷新失败而诱导重复提交。

计划模块接入时须把集合版本和未知补集纳入预检/发布校验，档期变化后标记受影响计划待复核；不能阻止成员修正真实档期，也不能把当前`not_implemented`当作无影响。资源登记与预约已在后续批次接入，见[资源与预约](resources-and-reservations.md)。

## 6. 验证边界

后端验证带时区/边界/重叠拒绝、跨日、双侧切分、未知补集、随机边界替换不变量、入组隔离、首次集合、版本与容量保护、提交失败及越权拒绝。前端验证明确核对、空集合清除、精确入组前提、冲突保留输入、未知结果不重复写及授权只读。

测试使用模拟数据库和现有隔离环境，不连接真实依赖或模型。真实迁移、两个窗口/多个进程并发、排斥约束实际生效、性能、计划复核与浏览器视觉仍待验证。

本轮新增34项后端和9项前端测试，全量442项后端、80项前端测试通过，TypeScript/Vite构建通过。前端首次全量发生多步骤用例总时限超时；独立复跑后，将整体时限设为10秒并限制同时2个jsdom Worker，每步查询仍限5秒。调整只影响测试调度和总时限，不改变产品超时、重试规则，也不构成性能验收。
