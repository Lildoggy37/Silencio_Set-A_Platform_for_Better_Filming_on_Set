# 正式排期撤回与发布通知回执

本批完成非Agent的撤回和回执查看，迁移头`0022_plan_withdrawal`。仅做离线SQL验证，未操作真实数据库、邮件服务或模型。

## 撤回规则

仅有`plan.edit + plan.publish`的当前在组成员可撤回当前正式排期，必须提供1—500字原因与当前版本锁。草稿、已被替代或已撤回版本拒绝操作。撤回后本计划没有正式安排，不恢复上一版本；重新安排需复制或新建草稿、重新检查并发布。

`PlanVersion.status`仍为`published`，表示曾正式发布；新增`withdrawn_at/withdrawn_by/withdrawal_reason`表示撤回事实，不修改原`publication_snapshot`。前端版本标签与正文显示已撤回，原回执和历史版本保留。清空`ShootingPlan.current_published_version_id`后，下一拍摄、跨计划冲突、成员退出责任及预约依赖等既有查询不再将该版本计为当前正式安排。

撤回在同一剧组协调锁和SQL事务中完成：权限与版本检查、指针清空、撤回元数据、版本锁递增、当前通告失效、取消事件、审计与幂等回执。相关当前通告（含此前待复核稿）标为`withdrawn`并生成通告状态事件；历史被替代通告保持已有历史状态。草稿和待审通告不强改正文，其来源校验会阻止继续发布。

复用`plan_action_receipts`，动作摘要包含`plan.withdraw`、版本ID、锁及原因；当前权限检查后、旧锁判断前返回原结果。同键异内容或操作者重入身份拒绝重放。结果未知时前端保留原请求与幂等键，手动重试；已知冲突刷新安排，不自动撤回其他版本。

撤回不取消资源预约、不归还实物、不改变库存，也不改变剧本或人物绑定，需按各业务入口另行处理。

## 事件与通知

`plan_publication_events`新增`kind=published/withdrawn`，旧行默认`published`，唯一键由版本改为`plan_version_id + kind`，每版最多一次发布及一次撤回事件。通知的事件引用仍独立唯一。

取消事件接收集合来自原版本参与人及当时入组身份。消费者重新检查当前在组身份、账号、通知和来源读取权限；匹配者生成`plan.withdrawn`站内提醒，不要求确认，不回写原已读或知悉记录。未运行消费者时只表示事件待处理，不能宣称已送达。

原发布通知失效判定增加撤回状态，且正确处理当前指针为`NULL`：禁止对撤回安排新增知悉，已有确认可按既有权限恢复原时间。仅本人相关权限的成员撤回后不能打开原排期详情，可读取其取消提醒；完整读取权限人员可查历史。

## 回执管理规则

本批只查询**排期／每日通告原发布通知**的回执，未新增任务全员回执、取消通知回执页、提醒重发或代人确认。

查看须有`member.read`，并同时满足：

| 来源 | 完整读取能力 | 发布责任或明确授权 |
|---|---|---|
| 排期 | `plan.read_all`或`plan.edit` | `plan.publish`或`notification.receipts` |
| 通告 | `call_sheet.edit/review/publish`之一 | `call_sheet.publish`或`notification.receipts` |

管理员身份不自动取得业务回执权限，只有本人相关读取权限也不能浏览全组名单。草稿返回409，异组或未知版本404。

列表以原发布事件接收集合为准，不按当前成员名单重新生成。排期包含上版移除后仍须收到变更提醒的成员，这些成员不要求确认新版；姓名从当时版本快照取得。通告从冻结的发布接收表取得姓名。成员ID与入组时间共同匹配回执，离组和重新入组不会覆盖旧记录；当下身份另列为在组、离组、重入或账号不可用。

| 状态 | 含义 |
|---|---|
| `pending_dispatch` | 发布事件尚未处理，当前没有该接收人的通知记录 |
| `generated` | 已有站内通知接收记录，不表示已送达到设备或已阅读 |
| `skipped` | 发布事件已处理，但该原接收身份未生成通知；不推测具体拒绝原因 |
| `read_at` | 本人显式标记已读的原时间 |
| `confirmed_at` | 本人显式确认该安排知悉的原时间，不代表到场、审批或任务完成 |

页头明确原来源版本当前是否有效、需复核、被替代或已撤回，失效来源显示历史提示。汇总的`read`包含已确认的人数，`unconfirmed`仅计已生成且原本需确认但未确认的记录，不是当前可执行的催办名单，也不把排队中的记录算作未读。

读取在剧组协调事务内获取观察时间、来源、事件及接收记录，避免混合撤回前后的状态；只批量读取当前页成员身份，不逐人查询。原事件集合与回执汇总在内存匹配，当前受既有场次／接收人数输入上限约束，尚未做容量验证或大规模SQL聚合优化。GET不写已读、不自动知悉、不触发重发。

## 接口与界面

均位于`/api/v1/crews/{crew_id}`，成功200。

| 方法及路径 | 输入／输出 |
|---|---|
| POST `/plan-versions/{id}/withdraw` | CSRF、UUID幂等键；`expected_lock_version, reason`。返回撤回版本、时间、原因、新锁、受影响通告ID及`notification_status=pending_dispatch` |
| GET `/notifications/receipts/{kind}/{id}` | `kind=plan/call_sheet`，`page`及`page_size`（1—20，默认20）。返回来源状态、观察时间、发布事件处理状态、汇总及原接收人的分页回执 |

撤回复用排期写入限流10次／分钟；回执复用通知读取限流120次／分钟，均按账号和IP限制。错误包括401/403、404、版本／状态／幂等冲突409、无效输入422、频率429及脱敏503。

排期页仅对当前正式版本展示撤回入口，先输入原因、核对影响，再确认执行。回执入口位于已发布排期及通告详情中，按权限显示；打开才请求、支持手动刷新和分页，失败隐藏旧私有数据，无自动轮询或代签入口。撤回及改绑后使当前剧组查询失效，刷新总览、通知、安排与回执。

## 验证与边界

定向验证覆盖撤回事务、重复请求、权限、当前版本竞争、通告失效、取消事件、通知查询中的空指针、回执分页／统计、历史入组身份、只读权限及接口约束。前端覆盖二次确认、原请求重试、来源绑定、历史提示、权限及加载失败。离线SQL保留旧发布事件，新增撤回事件不删除历史。

未进行真实PostgreSQL迁移、依赖服务联调、浏览器视觉验收或压测。迁移降级会恢复每版本唯一事件约束；已有发布与撤回双事件时降级将拒绝执行，不以删除事件方式强行通过。
